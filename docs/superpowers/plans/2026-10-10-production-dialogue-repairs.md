## 2. 七项根因、架构落点与同类场景

| 编号 / 用户问题 | 根因与源码证据 | 落点 / 同类场景 | 最小修复及验收位置 |
| --- | --- | --- | --- |
| 1. Markdown、SQL/DDL 代码块没有样式 | ARCHITECTURE §7 要求所有不可信内容 plain_text；feishu_render 不解析 Markdown。当前是有意边界，不是加粗渲染失效 | 渠道展示；分析、SQL 草稿、原始 DDL、反引号和围栏 | 受限格式解析与原文代码展示，保持原值；R12，涉及 C1 |
| 2. 有些回复卡片、有些还是文本 | feishu_render.build 按 facts 分流，无事实的建议/澄清用文本；符合既有契约，不是发送失败后偷偷回退 | 渠道构造；问候、澄清、草稿、有事实分析、固定回执 | 模型业务回复统一静态卡片；固定操作回执明确保留文本；R12，涉及 C2 |
| 3. 分析重复字段/表格/DDL，简短追问也重发整表 | DEFAULT_INSTRUCTIONS 已禁止复述，真实模型仍违背；Evidence.validate_answer 对每个引用总是生成完整事实 | 模型表达与事实展示两种根因；列库、结构、原文、历史条数追问 | 模型只解释；历史简短追问可用摘要视图，原事实不改；R3，涉及 C3 |
| 4. 会话太短、失效原因不清 | 20 次提交、400000 回放字节、7 天固定期限；PolicySession 多种失败合并，渠道记录无细分原因/提醒 | Session → App → 请求存储 → 双入口；长 DDL、多工具排障、最后提交超限 | 容量测算、有限调参、安全原因与同条提醒；R4 / §6，涉及 C4 |
| 5. 不能接收图片和文档 | feishu.py 在 message_type != text 时丢弃；Vertex._message 与 PolicySession 只接受文本；SDK 下载能力不等于产品支持 | 入站身份/下载/提取 → 模型适配 → 历史；截图、日志文件、说明文档 | 先准确提示不支持；另片贯通有限附件输入；E5，涉及 C5 |
| 6. 巡检结果不能交付 MD/HTML 文件 | AgentAnswer/Delivery 与发送链没有报告附件；ARCHITECTURE §2 暂缓导出/上传 | 事实生成 → 报告构造 → 上传/发送/重发；巡检、故障复盘 | MD 与固定模板 HTML 一起实施；E6，涉及 C6 |
| 7. 多集群同名表自行选 pre | cluster 是模型必填参数，路由没有默认 pre；治理证明允许访问，不证明用户本轮选择。已有“不猜集群”提示不足 | Agent 目标选择；表结构、布局、DDL、查数及源故障追问 | 明确目标来源与歧义规则；真实模型评估，R7；硬目标确认如需要另列 C7 |

七层归因：入口（文本/附件、身份、新建）→ 模型选择（目标、重复、意图）→ SDK/工具契约（显式 cluster）→ 治理（权限/参数/预算）→ Adapter（实际目标、SQL、结果）→ Evidence/Session（引用、回放与保存）→ 展示/发送（plain_text、容器、重复完整事实、容量、投递状态）。只在对应层修根因；不通过放宽 Evidence、改路由默认值或添加第二个模型循环弥补体验。

## 3. Agent 的任务、信息与自主范围

### 3.1 交给 Agent 的选择

在本轮权限、工具集合和预算内，Agent 根据缺少的信息选择工具、写查询、补取证、比较或结束调查。不规定“搜表 → 查列 → 查布局 → 查询”的固定顺序；已有准确限定表名和可见证据时可直接用适合的工具。报告请求也不固定巡检顺序，缺必要证据时自行补充，未覆盖项必须如实记录。

| 必要信息 | 可用来源 | 缺失时如何处理 |
| --- | --- | --- |
| 查询意图与目标集群 | 当前消息的查询意图；当前会话里用户已明确且仍适用的目标；仅一个合理的获准目标；§3.3 已明确的唯一可读匹配规则 | 多个合理匹配、发现不完整或引用不清时询问；不把最近工具用了 pre 当作用户选择，新建后无继承目标。共享群目标引用另按 §3.3 的用户决定 |
| 库表/字段、同名对象 | 用户限定名、可信业务说明、获准结构工具 | 可以按缺项搜索；无明确目标时依 §3.3 判定是否为唯一可读精确匹配，多个合理匹配则澄清。空匹配不证明不存在；已选目标不可用不改查另一源 |
| 时间、指标口径、单位 | 本轮可信时间、已配置业务时区/口径、用户、工具证据 | 只问影响答案的缺项；查结构不追问时间；解释/草稿不继承查询许可 |
| 原文、分页、结果完整性 | 结构化结果、next_cursor、真实截断标记、采集时间 | 原文不能先 SUBSTRING；分页与值丢失分开；预算不足基于已有证据说明只拿到部分 |
| 图片/文件里的说明 | 经准入的用户附件，仍是不可信输入 | 附件内容不能授予工具权限，不能替其他人发布指令；格式、能力或容量不支持则告知，不猜内容 |
| 报告事实、限制与结论 | 当前渠道获准 Evidence + 单列模型推断 | 无证据不写“已巡检/健康”；部分源失败则注明未核实，不能用模型记忆补事实 |

### 3.2 修正、继续和停止

复用 `ToolRejectedError`、SDK 工具错误回传及现有监控分类；不另建错误框架或模型循环。允许在现有拒绝异常上增加闭集的反馈标签，用于区分参数可修正、能力未开放、固定容量超限、前置检查自身失败、无权/范围拒绝、权限暂不可验证、调用预算耗尽、繁忙、本源停止和结构暂不可用；不是改动执行前/执行后分类、中止条件或现有监控续查契约。固定标签在可信拒绝分支赋值，不按异常原文猜类别。未知/隐藏工具仍沿原适配器/Runner 拒收，不纳入可修正反馈。

FunctionTool 的现有捕获分支直接返回小维固定结构反馈，可复用当前监控反馈的 JSON 形状；不再调用带统一“Please try again”前缀的 SDK 默认函数，也不读取 `str(exc)` 拼出模型说明。不修改 SDK、不用全局 formatter 冒充已修该分支。反馈表达“能修改什么”或“应停止什么”，不能把停止类拒绝写成可重试。必要时仅补已有参数 schema 的字段名/类型，不回显原参数、SQL、端点、异常原文或受限候选；失败反馈不生成成功 Evidence。

| 情况 | 同一 Agent 的下一步 / 必须保持的边界 |
| --- | --- |
| I/O 前参数、受支持 SQL 写法不合契约 | 反馈错误类别及可修改要求；在现有轮次、调用与期限预算内修改、澄清或结束，不再发相同错误调用。拒绝与执行计数沿现有机制，不新增一刀切重试次数 |
| 目标不明确、候选不唯一、可读快照无匹配 | 按任务澄清或补获准发现；合法空结果照常作为空结果引用。不能断言库表不存在，不能把字面 database 固定当占位词；搜索命中不是用户选源，满足 §3.3 的完整发现/唯一可读匹配时可按该规则继续 |
| 能力未开放、不可通过参数修正的固定容量超限、前置检查自身失败 | 停止相关操作并说明真实限制，retry_this_turn=false。有具体修正办法的游标/搜索/监控参数拒绝由可信点给闭集提示标识，映射固定改法，不读异常原文；搜索行过大但可以过滤避开的情形仍允许修改搜索条件，不混成固定容量停止 |
| 当前无权限、工具范围不允许、权限检查不可用 | 停止该操作，不换身份、越界工具或其他源绕过；只有仍符合用户任务的其他获准调查可继续。诊断隐藏工具和未知工具保持现行拒收语义 |
| 调用预算用完、SDK 步数达到上限 | 停止新增取证，仅在整轮期限内按现有回答/收尾与校验能力说明限制；无证据不伪造答案，不把预算拒绝当成参数可重试。正式路径断言之后无新增工具 I/O，并按当前 SDK max_turns、现有一次无工具收尾与总期限核对模型调用次数的确定上限 |
| 连接槽位繁忙，可信调用记录确认尚未发出任何 SQL | 保留现有执行预算退款，固定反馈给出繁忙类别、明确尚未执行及本轮剩余再试次数；Agent 可结束或在原期限/预算内选择再试。按用户 2026-10-11 批准的 C8，同轮同 StarRocks 目标至多再试 1 次，治理层在重新进入 Adapter/等待槽位前强制计数，换工具或参数不另给额度。本轮已在治理层实现并离线验证；发送过任何 SQL 的失败不进入此规则 |
| 已选目标结构暂不可用 | 固定反馈说明当前目标未执行，不建议同轮等待未知刷新/立即重试，明确不要改查其他集群；“稍后再试”只指后续用户请求。保留当前拒绝与预算边界，不将其误作繁忙槽位再试 |
| 已分类监控失败、PromQL 表达式错误 | 仅按 ARCHITECTURE §5 既有源级停止或表达式修正契约继续；不重发已失败表达式，不跨源偷换问题，不产生成功 Evidence |
| StarRocks 执行后失败、未分类执行异常或结果未知 | 沿现有工具失败路径中止，不自动重放。明确失败与结果未知不得混同；扩大可恢复的执行后分类须另提契约，不在本片笼统放开 |
| 整轮期限耗尽、会话不可安全回放/提交、Evidence 或最终回答拒收、不可修正协议错误 | 沿原链停止相关轮次，不另开收尾延长期限、不自动重写、不吞异常后继续；取消不证明远端已停止 |

目标不清时暂停具体表读取/查询。可为用户要求的跨源发现使用获准列库/搜表；用户明确比较多个源时分别取证并标明目标。权限、Evidence、接收授权和未来写审批仍是必要依赖。

本地构造失败且发送未开始为 failed；发送开始后结果未知为 unknown，不自动补发。操作者 requests resend 只复核并交付已保存结果，不重新调查或查询。Session 新建/关闭不改变 Action 执行事实。

### 3.3 两条目标规则（v3 审查 B1）

**唯一可读匹配，用户已决定（2026-10-10）：** 用户未指定集群时，按本轮授权完成必要发现后，恰好一个可读的精确库表匹配可继续读取；不必为这个唯一候选再询问集群。前提是所需候选范围的发现已完整、没有未核实的候选源、未完成的分页或仅有模糊/近似命中。说明“仅在 pre 的本轮可读范围内找到；其他集群未匹配不代表不存在”，不称全局唯一或把模型猜测保存成用户明确选择。与目标事实一起交付，沿现有 Evidence 校验，不为这些未匹配源伪造成功证据。发现不完整、源不可用或多个合理匹配仍需澄清。Agent 可直接先询问缺少的目标，不强制每轮穷举所有源；已明确目标或本轮仅一个合理获准目标不为了证明唯一再做无用发现。例外只解决未指定目标，不能覆盖用户明确目标、禁止执行或诊断工具范围。

**共享群目标引用，用户已决定（2026-10-10，2026-10-11 再确认）：** 群成员 A 明确说“看 fat 的 T”，B 追问“那它的布局呢”，引用明确且目标仍适用时可以沿用 A 明确指定的目标。只引用目标/对象，不继承 A 的指令或执行许可；B 的本条意图、当前身份/群/工具/源权限独立复核，符合 ARCHITECTURE G2/G4 的共享结果与当前请求边界。群历史谈及多个对象/来源、引用不清、目标已切换、新建后的旧历史，或目标只有模型上次调用而没有成员明确选择时不得沿用；澄清所缺目标，不重复询问已明确内容。


### 3.4 工具说明要求

沿现有工具名称、参数模型与治理接口修改必要说明，不新增测试专用产品覆盖入口：列库/搜表适合发现；describe_table 是字段、layout 是布局、show_create_table 是获准内部表原始 DDL；run_readonly_query 要有本轮执行意图和明确目标；每项简短写明适用问题、必要输入、目标要求、结果限制与可修正拒绝，以及不适合用它回答的问题；已知准确对象时不强制先搜索。示例顺序只作示意。报告导出不是数据库 SQL 能力，不能给 SQLGuard 增加 INTO OUTFILE 等语法。

C8 的具体风险是槽位超时退还工具执行预算，现有 max_tool_calls 无法限制同轮反复等待同一满载目标；SDK max_turns/总期限虽有界，仍可能被这种等待耗尽。已批准的契约给一次恢复机会，超过后停止该目标的再试，仍可做符合本轮任务的其他获准调查。只约束观察到繁忙后的新调用，不取消此前已在运行的调用、不改后台结构刷新。唯一再试运行中，同集群新来的调用在进入 Adapter/等待槽位前拒绝。若再试成功可继续正常取证，但本轮再试总配额不复位；之后再次繁忙不再给机会。未知执行结果无配额退款或重放，暂停不能当作远端已结束。次数记录与并发预占均在现有 GovernedTools/TurnRuns 路径完成，不另建定时、重试循环或预算平台。

### E5：图片和文档输入（第 5 项）

**先交付可独立的 E5a：** 对已授权且通过应用/租户/会话校验的非文本消息，发一条有界固定“不支持该类型，请发文字”说明；不下载、不调用模型、不查询。先核对事件类型、应用/租户、发送者、时间、消息 ID 与会话；指定群再校验平台 mentions 确为本机器人，单聊再查当前用户登记，之后才决定不支持类型回执。不能把当前早于群 @/名单查询的 message_type 拒绝直接改成回复。非指定群、未 @ 本机器人、伪造正文 @、非法/过期事件不回复；未登记的有效单聊沿现有有界身份提示，不创建业务轮次。沿已有去重/限频机制，重复事件不刷屏。

E5a 中富文本 post 与图片/文件同属未支持类型，不提取嵌入正文、不读取文件，也不把 post 内的 at 标签当可信平台 mention。先用合成协议验证带/不带有效 mentions 的群事件、已登记/未登记单聊、post 和重复事件；真实纯图片能否带本机器人 mention 尚未核实，不能用合成的正例宣称真实客户端已支持，也不新增跨消息配对或静默识图。

**E5b 附件格式方向已批准，实施须另获授权：** 第一版仅 PNG/JPEG 截图、UTF-8 TXT/MD 文档，建议单轮一个附件；PDF 的文本提取、Word/表格另按实际需求补，不假装自动支持所有文档。实施前固定每种格式、下载字节、图片解码像素/尺寸、提取文本、模型请求/回放容量和保留期；值由有界离线协议/容量实验给出，不直接照 SDK 的媒体缓存默认 50 MiB。

- [ ] 核对锁定 SDK 的公开 download_resource、入站 MediaContent、Model 输入项与 Session 支持；保持公开接口优先。当前 download_resource 完整读入并失败返回 None，缺少可证明的流式下载限额/精细失败码；先确认公开 transport 是否能补齐。无法在下载阶段有界时暂停 E5b，提出最小受控 HTTP 方案或锁版升级，不调用私有方法/monkey patch，也不以下载后检查冒充接收上限。
- [ ] 只用可信事件配对的 message_id/resource_key 取原消息资源，不允许模型传地址/键或猜其他消息；先复核当前用户/群与数据策略，下载、解析、入模各阶段限制独立。异步有期限/取消/清理，同步提取不得堵事件循环。
- [ ] 文档提取为有限不可信文本；图像经已核实的对应 Vertex/其他 Profile 输入映射。每个模型组合独立验证，文本默认行为不变，不跨供应商 fallback；unsupported 的 Profile 明确拒绝附件。
- [ ] 临时文件与回放记录归当前可信身份和 Session；开工前决定“不保存二进制只保存获准提取文本”或“保存限额内图像/不可外部转用的引用”的具体方案及TTL。不能写到SDK文本历史后声称支持图像续问；不能把Lark资源键当作永久可访问URL。

## 6. 第 4 项会话详细设计（原 v1 方案合入）

复用 SDK SQLAlchemySession 与已有 PolicySession，不用 SessionSettings.limit 取尾部裁剪。公开 Session 是唯一历史接口；提醒为可信渠道字段，不进入 AgentAnswer、模型请求或 SDK 历史。固定期限以真实 PolicySession 元数据为准，而非渠道映射创建时间。

### 6.1 状态与失败契约

采用一个有界的**可信会话状态快照**：观察时间、观察阶段、已提交轮数及限额、完整回放字节及限额、PolicySession 失效时间，以及可空的固定原因码。无法安全取得的计数留空，不能填零冒充测量值。快照不含问题、SQL、工具结果、Evidence 正文、签名、地址或凭据。

- 固定会话原因仅区分 `history_turn_limit`、`history_bytes_limit`、`expired`、`binding_changed`、`unavailable`；归属异常、损坏、失效证据等不能确定更细原因时用 unavailable。不要解析异常文字。
- `phase` 区分开始前、提交前、提交后；只从可信执行阶段产生，不从模型/远端取得。
- 外层仍保留 `session_unavailable` / 已存储的 `session_failed` 类别；日志追加 `session_reject=<闭集>`，保留原有 answer_reject/tool_error 等，不修改其他失败含义。
- 请求终态与快照同次应用表事务保存；completed 的快照只能来自成功提交，失败快照不能把未提交轮次计入。Session/应用表仍不假设跨组件原子，保留 result_not_saved 关闭规则。
- 用现有请求表增加一个可空、校验并限长的状态字段；总编码上限拟为 1024 字节：只容纳固定状态字段，防止附加字段成为正文旁路；现有 max_answer_bytes 只保护回答列，不能覆盖新增字段。不挤进 AgentAnswer/失败正文，不新增状态服务或通知表。旧请求为空，保留旧回执，不追溯猜原因。
- 显示用提示从快照的固定字段生成，加入渠道 Delivery 的可空系统提醒；只在已通过当前身份读取后展示。事实、推断和系统提示分开。
- 历史/重发显示“本轮结束时”的快照，不把旧剩余额度当成当前余额；不重新回放历史来更新一个旧提示。
- 在原本计算完整回放字节/读取会话元数据的位置取快照；不为提醒再做一次 Evidence 复核或全量回放，不多占 max_scope_checks。
- 快照非法时拒绝该记录的交付，不静默丢掉必要提醒；关键保存失败沿现有受控失败路径，不吞异常。

这需要一次显式应用表迁移；基线为 v6，实施时协调监控分支后分配下一个版本。保持失败码 CHECK 闭集及 SDK 自有表不动。接口字段的具体命名/内部函数留给开发；上述数据来源、事务和外部行为先锁定。

### 6.2 用户看到的结果

| 场景 | 默认可见的说明 |
| --- | --- |
| 达到已提交轮数上限 | “会话已达交互轮数上限。请新建会话继续；之前的上下文不会自动带过去。” |
| 历史字节达到上限 | “会话历史已达容量上限。请新建会话，并补充目标和关键线索。” |
| 本轮执行后提交超限 | “本轮执行后历史超出容量，回答未保存/交付，会话已封存；已执行的工具不会自动重试。” |
| 已过期 | “会话已超过保留期限。请新建会话；原历史不能继续回放。” |
| 模型/数据策略绑定变化 | “模型或数据策略已变化。请新建会话。” |
| 其他不可继续 | “会话历史不能安全继续，请新建会话；已执行操作不会自动重试。” |
| 未达到限额 | 正常结果；没有长篇实现说明 |

按渠道补最短操作指引：Web 点“新建会话”，飞书发 `/新建`；新建不等于立即删除保存记录。这里只修固定提示，不增加自然语言命令帮助功能。

接近上限：在**成功提交并保存**的同一条回复中，轮数达到限额的 80%、历史字节达到 80%，或 PolicySession 距过期不超过 1 小时，显示一条短提醒。合并命中条件，达到阈值后每个成功轮次最多一条；不加后台计时器、额外消息或告警状态表。

示例：“本轮结束时会话已用 80/100 次；历史容量接近上限。后续可能需新建会话，关键线索请自行保存。”不能说“还能保证聊 20 次”，字节、期限或证据失效可能先到；会话期限也不保证每条历史证据仍可复核。最后一次合法提交明确“下轮需要新建”。

### 6.3 会话契约取舍（提案，未生效）

1. **轮数已批准 20 → 100，待 R4 实施授权。** 仍是有界上限；本片不取消期限、字节、权限或数据复核。只是允许更多完整历史回放，会增加耗时、模型输入用量和复核成本。
2. **字节与模型请求暂不拍脑袋调大。** 先比较当前 400000 / 1000000 与代表性排障样例；容量报告决定是否足够。若需增加，先给出最小成对数值、请求开销与预算证据，再获用户批准；不能以 100 轮为名顺带放宽四种投影、结果/响应/工具预算或 7 天期限。
3. **新增可信提示字段与应用表迁移。** 目的是首次投递、轮询、历史和重启后说明一致，不改变 AgentAnswer / Evidence 格式。旧客户端可忽略新增显示字段；旧镜像不能直接运行升级后的应用表，回退需明确迁移/恢复路径。
4. **提醒占渠道容量。** 默认可见，计入现有文本/卡片两项容量预算；沿既有事实优先与固定容量说明契约，不多发一条、不挤掉限制后冒充完整结果。

没有新增 Agent 硬步骤或更低资源上限。80%/1 小时是展示阈值，不阻断任务。更大的上下文能否保证真实模型更好排障仍是待验收问题。
