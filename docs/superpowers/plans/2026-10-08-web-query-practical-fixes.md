## 场景与判据

| 用户实际问法 | 必须做到 | 当前发现 |
| --- | --- | --- |
| 有哪些库／show databases／只要库名 | 专门枚举有可读对象的库，分页至末页，说明可见范围；不猜关键词 | 只有关键词搜表工具，库名靠表搜索拼接会漏 |
| 某库有哪些表／全部列出／继续下一页 | 指定库可不带关键词遍历；同一目录的定时刷新不打断分页 | 必填关键词；每次刷新换游标版本 |
| 搜订单表／两个库同名表／找不到表 | 搜索与遍历分清；返回限定名；未找到不等于不存在 | 保持现有歧义拒绝与权限探测，加入样例 |
| 查看结构／varchar 多长／金额几位小数 | 保留完整字段类型；不得凭 id 字段猜主键 | 采集 DATA_TYPE，丢失长度与精度；对话中确有主键误述 |
| 主键／排序键／分区／桶数 | 从布局证据回答，复合主键不省略；未知值不补故事 | 字段结构不含主键；buckets=0 的解释无足够证据 |
| SHOW CREATE／默认值／属性／视图定义 | 明说目前不支持原始 DDL；不能用字段摘要冒充建表原文 | 当前有意不开放原始 DDL/PROPERTIES；本次不扩大数据边界 |
| 只要结果／只列名字／查看依据 | 主回复简洁，证据可展开；不重复渲染 JSON 与表格 | Web 同时显示完整 content 和 facts |
| 给我完整原始结果／订单号／空值／JSON 字段 | 获准结果原文可展开，长整数不舍入，NULL 与空串分开，嵌套字段不丢 | 独立审查在真实 StarRocks + Chrome 复现大整数舍入、空值混淆与嵌套字段丢失 |
| count／sum／去重人数／昨天／最近十条 | 聚合不能被截断前明细代替；明确时间/单位/排序口径 | count 样例正确，其余作为实战样例，未证明有缺陷 |
| 换个集群／刚才那张表／重新查最新 | 保持目标归属，歧义澄清；历史不是本轮重新执行 | 既有边界需回归，不推定全部有故障 |
| 为什么慢／只写 SQL／不要执行 | 默认 Agent 按当前意图选择；显式诊断入口零实际查询 | 保持既有行为与硬边界，真实模型样例需单列 |
| 失败后继续／超时／证据失效 | 请求号能定位阶段；不盲目重放已执行操作 | Web 合并多个失败码；原失败根因待运行日志 |

纠正一项判断：Evidence 的 information_schema SQL 是结构快照的采集来源，关键词在缓存内匹配，不能仅因 SQL 没有关键词条件便断言模型编造了搜索。原对话的 COUNT=71526 与证据一致；未将它列为缺陷。

## 实施顺序

1. 在现有结构缓存、工具治理与分页路径上补齐目录枚举；列库只包含至少一个当前可读对象的数据库，不声称列出了空库或无可读对象的库。新增能力须明确配置工具授权，不能自动扩权。
2. 保留完整类型；相同快照内容保持游标版本，内容变动仍拒绝旧游标。字段、主键、布局与原始 DDL 的能力界限进入工具说明和固定事实说明。
3. Web 主回复使用结构化事实渲染一次，分析与结果分开，来源、SQL 与本次获准结果原文可展开。原文保留值与类型；大整数在浏览器解析前转为展示文本；NULL、空串与缺失值区分，嵌套字段完整保留。分页/截断仍明示，不能把本次有限结果称为全部。避免用“已完成”暗示业务请求必然满足。
4. 针对已证实问题补回归，扩展既有固定任务样例。仅在获准模型与正式入口跑过后才记模型/实战通过。请求关联日志用于解释原失败，不凭聊天回执认定根因。
5. 本轮时钟由每轮新建 Agent 的 instructions 提供 UTC 时间；昨天/今天结合业务时区，不让模型把旧采集时间当现在。未知业务口径仍澄清。请求号与内部 turn 的对应关系只记录编号并转义控制字符，不记录问题正文或上游错误体。
