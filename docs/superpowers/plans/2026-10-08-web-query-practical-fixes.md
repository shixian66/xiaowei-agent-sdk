## 实施顺序

1. 在现有结构缓存、工具治理与分页路径上补齐目录枚举；列库只包含至少一个当前可读对象的数据库，不声称列出了空库或无可读对象的库。新增能力须明确配置工具授权，不能自动扩权。
2. 保留完整类型；相同快照内容保持游标版本，内容变动仍拒绝旧游标。字段、主键、布局与原始 DDL 的能力界限进入工具说明和固定事实说明。
3. Web 主回复使用结构化事实渲染一次，分析与结果分开，来源、SQL 与本次获准结果原文可展开。原文保留值与类型；大整数在浏览器解析前转为展示文本；NULL、空串与缺失值区分，嵌套字段完整保留。分页/截断仍明示，不能把本次有限结果称为全部。避免用“已完成”暗示业务请求必然满足。
4. 针对已证实问题补回归，扩展既有固定任务样例。仅在获准模型与正式入口跑过后才记模型/实战通过。请求关联日志用于解释原失败，不凭聊天回执认定根因。
5. 本轮时钟由每轮新建 Agent 的 instructions 提供 UTC 时间；昨天/今天结合业务时区，不让模型把旧采集时间当现在。未知业务口径仍澄清。请求号与内部 turn 的对应关系只记录编号并转义控制字符，不记录问题正文或上游错误体。
6. 模型失败日志只记录固定 `error_kind` 和受限整数 `http_status`，区分请求/响应边界、模型输出契约、HTTP、连接、模型调用超时、拒答、SDK 配置及未分类异常。不读取异常正文、请求、响应体或动态异常类名；不改变现有失败码和不自动重试规则。

## 内部表原始 DDL 增量（用户已确认）

用户已明确选择“本轮补齐内部表原始 DDL”。新增独立授权的 `local/show_create_table`，参数只有集群、
库和表；只支持当前可 SELECT 的普通内部 OLAP 表。快照先拒绝视图/非普通表；读取原文前后以固定
元数据模板确认对象 ID、类型、引擎未变，再经现有 Evidence 权限与版本重验。外表、外部 catalog、
视图和物化视图不开放。实际执行固定 `SHOW CREATE TABLE`，不执行返回的 CREATE 语句，不从字段拼接。

返回数据库原文（含默认值、键、分区定义与表属性），不承诺它等于操作者当初输入的 SQL，也不把
DDL 当作当前分区状态列表。新增可选 `max_ddl_bytes`，未配置时沿用 `max_value_bytes`，仅此工具使用；
仍受 `max_result_bytes` 与四种投影容量限制。超限整条原文不交付，结果明确标记未取完整及限额原因，
不把半段 DDL 当可用建表语句。Web 使用者示例明确配置此限额与工具授权，飞书群示例不增加 DDL 授权。真实只读账号输出逐字对照、撤权/跨目标/
外表/视图/对象替换拒绝、容量与 Web 原文展示都纳入检查。
