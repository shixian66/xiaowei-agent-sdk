### 本轮提出的契约变化

1. 提示词中的工具顺序改为按需取证；时间只在业务需要时澄清；完整原文请求不主动截短。这不授予新工具或执行权限。
2. 有成功证据但需要补充条件时，在现有证据回答的分析里提问；三种最终类型仍互斥。
3. 飞书结果从纯文本改为卡片；事实、采集时间、固定说明及不完整提示默认可见，分析在事实之后单列为模型推断。技术详情可折叠。
4. 飞书超容量时，优先保留证据归属、时间、必要说明和结果，再安排分析；不能让分析挤掉全部事实。这会改变现有“先保分析”的截断优先级，须在 U2 交付中明确说明并据批准契约更新相应测试。

## 3. Global Constraints

- SDK 是唯一 Agent Loop，不新增 Planner、前置用途分类 Agent、固定业务流程、调度器或模型文字解析执行器。
- 每次 I/O 前的权限、目标、参数、SQLGuard、预算复核全部保留；显式诊断轮继续隐藏并拒绝真实查询工具。
- 本轮全部成功业务查询证据仍须引用；Evidence 拒收仍失败，**本轮不做拒收后自动改写**。
- 历史读取、首次发送与显式重发均重新验证当前权限、来源、归属和接收渠道；权限撤销仍阻断。
- 四种投影独立；飞书只读 `feishu` 投影，不能借 Web 投影获取更多结果。仅折叠不会减少 payload 大小。
- 原始结果与展示截断分别如实标记；不会因好看而丢列、丢行、改数值、拼 DDL 或声称取全。
- 保留 `max_reply_chars` 的 200–3500 校验；所有可见/折叠文字都计数，包括标题、表头、列名、值、来源、SQL、说明与依据编号。还须满足 SDK 最终请求体字节上限；任一上限先到就裁剪，不自动提高配置。
- 一轮结果只发一条消息、一次发送；发 SDK 请求前的本地构造/渲染失败记 `failed`，不锁飞书 readiness。进入 SDK 发送或任务调度后，沿用明确失败与结果不明的区分；超时/取消仍不能推断未发送，不自动重发或改发另一类型。存储写入或投递权异常的保护仍保留。
- 不增加数据库表或迁移，不改已有投递状态机、不增加已读推测、不自动重跑历史查询。
- 不新增附件导出、公开结果链接、卡片回调/分页按钮、动态更新或流式消息；这些需要另行定义数据与投递边界。
- 本次实现和验证不调用真实 Vertex、飞书/Lark、公司 StarRocks 或监控源，不发布、不部署；本地审查已完成，用户 2026-10-10 批准按 §8 的例外开 PR、合入。真实评估和部署后人工验收在获准环境单列。
- 浏览器验证只用 18501 或其他空闲端口，不占用或停止 8501。

## 4. Review Focus

- 元数据多页、空页仍有游标、游标失效、预算不足：不能把部分页当全部，也不能无限翻页。
- 历史回答已提交但发送超时：继续追问不能被解释为用户已经收到了；再展示仍验证当前权限。
- 长文本包含真实换行、字面 `\n`、双向控制符、`<at>`、管道符与反引号：显示编码可转义，不能把数据变成卡片结构或消息指令。
- 宽表、大整数、真正 NULL、字符串 `"NULL"`、空字符串与缺字段：保留值的区别，不能靠 Markdown 反解析结果。
- 卡片中数据库值、DDL、模型分析和澄清/建议原文只进 `plain_text` 或纯文本单元格，不进 `markdown/lark_md`；伪装链接、图片、`<font>`、代码围栏和 mention 都须有反例，不能仅依赖文本消息的 `mention_safe`。
- 卡片超容量、发送被取消、SDK 明确失败、重复飞书事件：只允许一次发送，保持 `sent/failed/unknown` 的真实状态。

### U1 的工作方法提示词要点

保留可组合的工具用途、补证据方法与停止条件，而非只删掉规则：

### 两个容量预算的定义

1. **字符预算：** 以显示转义完成后的 Python `len(text)` 计 Unicode 码点。可见与折叠文字都计入：标题、表头/列名、值、来源、目标、采集时间、note、依据编号、分析、SQL、游标、截断提示和固定说明；同一文字显示多次就重复计数。纯结构键、样式和内部标识不计字符，但全部计入字节。文本消息也采用同一文字口径，不让 SDK 通过拆分绕过单条上限。
2. **字节预算：** 保守内部上限为完整 HTTP 请求体 UTF-8 的 `30_000` 字节；Step 1 核实目标消息 API 限制，必要时只能取更低值。不能只量内层卡片 JSON，也不另设代替最终请求预算的 24 KB 估计。按公开 create/reply 请求格式计入卡片序列化为字符串、外层 JSON 的再次转义、重复列名、收件人、固定长度 UUID 及回复封装。仅复用公开数据格式，不调用 SDK 私有编码器；用真 SDK 合成端点对两种封装逐项证明预算计算不低估实际请求大小，边界用例的实际请求体均不超限。

容量分配是确定性的：先预留所有来源与必要限制、SQL 展示状态和可能的截断提示，接着放实际业务查询 SQL，再按证据顺序保留完整结果行，最后放模型分析。SQL 排在结果行和分析之前；容量放不下整条 SQL 时保留默认可见的“SQL 未展示”。这项先后顺序由确定性测试锁定。任一预算先触顶即停止；分析被截短或整段移除时必须有默认可见标记。最小固定容量说明仍须满足两项预算；计算或渲染本身异常时记 `failed`，不能假装已发送说明。
