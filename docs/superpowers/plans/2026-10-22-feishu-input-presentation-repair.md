# 群消息输入与按需详情最小修复计划

> v1.1，2026-10-22（Asia/Shanghai）。已归并用户确认的长期交付规则；仅文档，未实施。
> 获得开发授权后，按 AGENTS.md 和 executing-plans 串行实施；本轮不写功能代码、不调用真实服务、不推送或部署。
> 基线：main@1a92c58da5a47db755fb3213c9fd9e0393511e01。文档分支 codex/feishu-input-presentation-plan，复用干净的代理隔离工作树；原目录及暂停的 D 工作树保持不动。

**目标：** 落实长期交付规则，让用户直接获得任务所需的结论、关键事实和执行状态；获准群内文字/富文本可接入，图片已开启时复用一张截图及同条问题的既有诊断能力。

**权威契约：** [ARCHITECTURE 长期产品规则](../../../ARCHITECTURE.md#user-delivery-and-history)唯一维护交付与历史详情原则，[群输入增量](../../../ARCHITECTURE.md#feishu-input-presentation-repair)维护本次输入范围。本计划仅维护事实、实施范围、接口门槛和验收，不另建 spec、不重复长期规则、不重开旧 P2/P1 修复。历史测试不证明新体验已通过。

## 1. 源码事实与复用落点

| 事实 | 落点与判断 |
| --- | --- |
| 工具标题与逐条依据入口由程序生成 | feishu_render.py 的 fact_elements / fact_details / 卡片标题、static/app.js 的 factTable；只改提示词不能解决 |
| 通知有独立纯文本渲染 | webhook.py 的 _notification_text，C 后台也调用；不能只修普通卡片 |
| 全部模型可见 Evidence 先复核，再组装输出 | EvidenceStore.validate_answer；保留当前权限、接收范围、来源、归属、TTL 和依赖校验 |
| 群 text 可接入，post 当前直接拒绝 | FeishuGateway._parse / _receive；已用合法平台 @ 的合成群事件复现，生产这条消息的类型仍未知 |
| 图片功能并未删除 | _image → 受控下载 → validate_image → save_image / SessionImageStore → Application.run_turn / Vertex 原图回放；复用单张 2 MiB、每会话 12 张及原尺寸限额 |
| SDK 有公开纯解析能力 | 锁版 Lark Channel 1.4.0 的 normalize.parse_message_content / flatten 可取文本和资源；但 flatten 会把 image_key 拼入 Markdown，不能原样交给模型 |
| 当前展示意图只有 full/brief | models.FactBlock；brief 仍承诺原值随消息/附件交付，须验证能否表达新要求 |
| 回执与恢复已有实现 | Delivery.notification_notice、receipt_notice、任务状态和既有 Action 材料；复用，不建新回执存储 |
| 已有历史读取范围有边界 | ResultDelivery 读取已存回答、Session 按 Evidence 引用回放、get_task 读任务状态；不是任意跨会话历史检索，也不保证保存完整响应/执行轨迹。保存过不等于当前可展示 |

用户只提供了回答粘贴和展示标签，没有生产镜像 SHA、请求编号或原始入站体。源码和合成复现证明机制可达，不证明生产实际分支、图片开关或模型识图质量。

## 2. 本次应用范围

展示、历史详情、缺失数据和刷新行为直接遵循[长期产品规则](../../../ARCHITECTURE.md#user-delivery-and-history)，本节不另维护一套默认交付契约。

- S1 覆盖飞书、Web、MD/HTML、A 即时通知、B 新建提醒内容与 C 后台结果的实际消费者；关键事实仍由代码从获准投影生成。任务状态使用可信业务回执，保留可查询/取消的任务 ID。
- 审批材料的标题可自然表达，必要内容、审批绑定、失败/unknown/未完成及重复风险不变。原群与目的群的读取/接收许可不互相继承。
- S2 仅接通获准群内文字 post 与含一张图的 post，保留同条问题；图片复用原诊断用途。独立图片、TXT/MD、文字命令和单聊不退化，不增加多图、图片外发、跨消息配对、单聊 post 或 Web 图片入口。
- 图片开关与现有模型组合不自动改变；普通 post 的真实用户正文可走原文字命令入口，截图/引用资料中的命令仍是不可信资料。
- 官方 Webhook / feishu_proxy 保持已批准的纯文本协议，不增加富文本/图片通知。已保存提醒正文、发送机会、已绑定消息/文件不回写或自动重发。

## 3. 最小实现与依赖

### S0 — 先闭合展示意图与公开 SDK 两个接口门槛

- [ ] 用合成回答证明：①普通三行业务表直接可见，内部 SQL/字段不默认附送；②用户以 SQL/DDL、代码、表格或文件为任务结果时照常交付；③索要同一证据详情时仅返回实际保存且当前获准的内容；④普通任务状态无内部包装。必要业务进度保留，不把它当工具调用轨迹删除；不能靠长度或关键词正则猜意图。
- [ ] 优先复用 full/brief、有序块及已有受治理读取入口，并明确每个详情样例实际由哪个入口/可见历史支持；不能从“库里有记录”推导 Agent 可任意检索。若两值不足，先展示反例，选择最小回答契约调整，写清 Provider schema、旧记录和旧程序读取影响，再实施；不预建展示平台、通用历史检索、行列 DSL 或持久化版本。
- [ ] 核实公开 post 解析的正文/资源分离，覆盖锁版支持的 locale/直接文档和 content/content_v2 形态，不能出现正文取 v2、图片却只取旧字段的遗漏；标题、段落、换行、常见格式文字和代码原值保留；图片引用仅在受控内存中使用，资源键不进入模型正文、SDK 历史或日志。
- [ ] 复用公开纯函数，对 SDK 会宽松跳过的非法结构/媒体做薄层校验；不调私有 API，不启用默认媒体下载、转发展开或第二个入站处理器。

**退出：** 两类展示意图可区分；文字 post / 一图 post 能生成现有入口可消费的有界内容，零网络 I/O。接口/兼容未解决时只暂停依赖部分，不用模糊契约开工。

### S1 — 默认业务回答与按需详情

**范围：** app.py 指引；evidence.py / models.py 仅限 S0 证明必要的输出组装；feishu_render.py、static/app.js、webhook.py、feishu_report.py / feishu_delivery.py 的实际消费者；任务与通知回执复用原模块。

- [ ] 先补失败样例：普通任务状态、巡检和查询不出现内部包装；确认材料及 unknown 风险可见。
- [ ] 保留已校验的 Delivery / Evidence，不删除底层事实，不减少全部模型可见数据的接收校验。关键事实由代码从获准投影生成，模型说明不冒充核实值。
- [ ] 非表格 Prometheus result 在获准投影中按原策略保留，不默认铺开原始响应；不以正则猜样本/标签或模型重写生成“可信指标表”。若当前投影不能保真交付用户所需的关键事实，作为 S0 具体反例解决，不能静默省略；不夹带 D 的读取/巡检算法。
- [ ] 根据展示意图输出业务正文或索要的详情；不把所有未引用结果自动附到默认消息/文件，不为短回复自动生成证据附件。派生回答/文件仍按既有策略保存并继承最早依赖期限，不扩大字段/保留范围或给原记录续期；复用必要纯渲染函数，不建渠道框架。
- [ ] 飞书、Web、A 即时通知及 C 后台结果采用同一约定；B 新建内容经同一路径，已存提醒正文、发送机会和绑定消息/文件不回写、不自动重发。
- [ ] 明确索要的原文仍受投影/容量限制；放不下复用已有文件分项。代理没有附件机制，沿原超限拒绝或 C 固定容量说明，不拆发、裁剪、改投。
- [ ] 默认业务回答送达不等于原始明细已交付；明确索要的内容缺失仍是未完整。历史详情不重跑原业务任务/重复副作用；当前权限复核允许必要元数据 I/O。用户另行要求刷新按新任务执行并标明新采集结果，不冒充旧数据恢复。保持原字节恢复、claim/settle、防重、unknown 提示送达绑定。

**退出：** 尽早跑通正式群入口的一次成功和一次 unknown/拒绝，再补各载体、历史、审批、容量与恢复边界。

### S2 — 群内富文本接入与既有图片能力复用

**范围：** feishu.py 的 _parse / _receive / _image 及必要的小型纯解析函数；channel.py、app.py、image_input.py / Vertex 只在现有接口不能携带同条问题时局部调整，不重写原图存储。

- [ ] 先补“同一句话 text 可进、post 被拒”的失败测试，再接纯文字 post。
- [ ] 仍从 raw 事件核对 app/tenant、指定群、发送者、时效、平台 mentions 和当前成员；正文 at 或机器人名称不授予入口资格。
- [ ] 公开 SDK 处理受支持正文，按现有 JSON/文字/模型字节预算校验，不截短。链接只作文字；多图、未知媒体或非法结构整条给准确说明，不悄悄只处理第一图/残留文字。
- [ ] 一图 post 和独立 image 共用受控下载、解码、容量、原图保存、诊断 Runner 及后续回放；同条用户问题随图交给模型，图片里的文字仍是不可信资料。
- [ ] 图片开关、已审定 Vertex 组合、12 图/尺寸/TTL 限制不变；不自动改公司配置或 fallback。图片未处理时不能把整条图文当已分析完成。
- [ ] 未授权、其他群、无可信 @ 时下载/模型/业务 I/O 为零。取消、保存失败、原图回放和 readiness 沿原机制；旧 text、TXT/MD、单聊和审批不回归。

**退出：** 正式 Gateway → ChannelService → Runner 上，文字 post 成功；一图及追问的原图/问题到达模型替身；未授权、损坏/超限失败可观察且无越权 I/O。

S1/S2 可独立验收，复用 S0 调研，按项目默认串行完成；D 保持暂停。

## 4. 权限与失败提示

单 Agent / SDK 唯一 Loop、工具治理、SQLGuard、Evidence/Session、接收范围和生产写逐次审批保持。不新增权限来源、审批体系、凭据配置或服务。

| 情况 | 提示与执行边界 |
| --- | --- |
| 无平台 @、其他群、确定无权 | 沿原忽略/拒绝规则；零下载、模型和业务调用 |
| post 非法、多图或不支持媒体 | “这条图文未处理：……；请改为文字或单张 PNG/JPEG。”下载/模型前拒绝，不静默丢节点 |
| 图片开关关闭 | “当前入口尚未启用图片分析，本条图文未处理。”不声称永久不支持；不自动开启或换模型 |
| 管理员配置了不兼容的图片模型组合 | 复用现有启动配置校验拒绝，不新增不可达的运行时兜底分支 |
| 图片过大/损坏、会话额度满 | 复用原具体提示；不缩图、取第一张冒充完整 |
| 下载、保存或核验暂时失败 | 如实说明本次未处理/当前无法核实；状态按原阶段保存，不谎称模型已看过图 |
| 详情未保存、已清理、过期或当前不可读 | 如实说明已知缺失/截断及不可读取范围，不声称完整原始结果可恢复，也不为补旧数据重跑；用户另行要求刷新时作为新任务按原授权执行并明确是新结果 |
| 代理 2xx / 发送 unknown | 分别说明“代理返回成功状态，群内投递未确认”或“结果未知，可能已发送，不会自动重发”；风险不藏详情 |
| 待批准、批准失败、预算/数据不全 | “尚未执行/未激活/未完成”，保留必要材料及未核实范围 |
