## 3. 最小设计

### B1：只补快照统计日志

每次刷新记录原始对象行数、列结果覆盖的对象数、因无列丢弃的对象数、因标识不安全丢弃数，保留现有候选数/可读数。原始行数与去重对象数明确区分，过滤原因按现有过滤顺序计一次；列名冲突若需要对齐账目可另计一个固定原因，不改变过滤。

不记录库表/列名、注释或 SQL。无列对象仍按现状过滤，合法稳态不因诊断变成刷新失败；不设置“减少多少就拒绝”的阈值。用已存在元数据超限/探测失败用例确认旧快照保留与过期规则不变。

### B2：刷新放在已治理、有预算的异步执行阶段

保留同步 Prechecked，不扩展成通用异步前置检查框架：

1. check 继续做参数/绝对窗口、当前快照和已有固定列检查。快照存在但审计表缺失时，返回带规范化窗口、待复核标记的准备值，不把缺失直接当最终拒绝；不读库。
2. 治理完成当前授权、准入与预算预留后，`inspect_security` 的 async run 处理待复核：若共享快照已经恢复就直接用新对象，否则至多调用一次现有 `schema.refresh()`，再复核。
3. 刷新成功且表/固定列满足 → 绑定新快照的 read_dependency，正常聚合、粗筛与精判；成功仍无表 → object_not_readable（已刷新复核）；失败 → schema_unavailable，保留旧快照，不报为缺表。新表缺固定列仍为 unsupported。
4. 刷新后仍缺表、缺固定列或刷新失败时，审计读取未执行，但已经发生合法结构 I/O，**计一次工具预算**。用本片窄类型的未完成结果交回治理/工具层，不把执行阶段任意 ToolRejectedError 全局放行。刷新成功后，审计 SQL 发出前的槽位繁忙仍沿既有 busy 退款/一次修正规则；不得把这种退款说成整次调用从未发生任何 I/O，刷新本身受既有结构资源限额约束。

等待受 Application 本轮剩余期限与 schema 自身刷新期限约束，超时后该调用不再进入审计读取；不加等待刷新循环。已有 refresh 用 shield 共享任务：一个等待者到期不取消其他等待者的刷新，底层可在自身既有限额内收尾，不声称远端立即停止。原“无/过期快照”的通用规则不顺带修改。

共享刷新任务在干净的 context 中创建，避免继承调用方的 SQL I/O trace 和轮次上下文；用 Python 3.11 原生任务 context，不全局清空其他调用的 trace。沿原 `_inflight`/shield 共享同一次刷新，不为每个等待者另建刷新。回归覆盖刷新后首次审计槽位超时仍为 busy、预算按上段处理，以及一个等待者到期不取消其他等待者；相关离线回归已执行，精确命令与结果见 handoff。准备值到实际执行期间快照可能变化，重读当前对象是状态变化后的复核。

### B3：只对本工具返回明确的读取未完成结果

推荐采纳单工具例外，依据是本工具只有固定只读采集 SQL；失败时继续其他目标没有业务写副作用，且能保留已取得事实。沿现有 monitoring read 的“记账→返回固定失败→代码提示”路径增加窄的安全巡检类型，不把监控类型/白名单扩大成通用失败平台。

- `object_not_readable/schema_unavailable/unsupported` 准备结果和本工具已分类的 StarRocks 源错误，返回固定 `status/code/reason/target/window`，无成功 Evidence、无伪造零计数；工具回调本身不重放。
- 执行错误只接受现有固定错误码的窄集合：connect_failed、auth_failed、session_setup_failed、permission_denied、object_missing、object_unreadable、query_failed、server_timeout，以及 timeout/connection_lost。busy 的 SQL 前槽位拒绝沿既有路径处理；预算耗尽仍不执行。
- timeout 在本工具固定反馈和提示中使用中性说明：“读取或分析超时，未取得可交付巡检结果”；SQL 可能已返回，不能仅凭此码声称远端仍在运行。connection_lost 说明连接中断、结果未知，不能归为未执行；server_timeout 可说明服务端终止。query_failed 不能臆测为内存不足或语法错误。未知执行结果仍不自动重放；无需为本次文案增加错误平台或改变通用查询的错误契约。
- 未知程序异常、结果契约破坏、Evidence 保存/权限失败、Session 失败仍中止轮次；不以“可继续”吞掉可信事实边界。其他工具和写动作原契约不变，写操作未知结果更不能按此返回后继续执行。
- object_not_readable 的通用反馈改成“不得用其他集群替代本集群；用户已明确要求的其他集群照常调查”。本工具已刷新仍缺的专属反馈说明已复核，不要求 Agent 先跑额外结构查询或固定修复顺序。

这是对 [ARCHITECTURE §5/§6](../../../ARCHITECTURE.md#6-只读查询保护)“非监控执行后失败中止”规则的**明确窄范围契约修订**，计划获审后才能实施，不借安全 Skill 绕过执行层。

### B4：最小失败记录、成功 Evidence 与交付

“取得结果”指本轮该目标/窗口已有成功保存且通过当前权限校验的 Evidence；“分类计数完整”仍只由 coverage 声明，二者不等价。候选截断、无法判定或只省略样本但已返回有效 Evidence，均不作为取数失败记录。

仅增加 `SecurityInspectionFailure`（可信内部类型，模型不能填写），保留未取得可交付结果的调用之工具、规范化目标、绝对起止、采集时审计时区、审计 SQL 是否已发出（不含共享结构刷新）、固定原因码与 SDK call_id（提交时绑定来源依赖）；关联沿用本轮既有调用顺序与请求归属。不含 SQL、账号、样本或异常正文，不保存成功记录或成功 Evidence 的镜像。成功继续使用既有 produced 与 Evidence，取其目标、window、coverage 和采集元数据。

仅为已确认路由和窗口的准备拒绝、busy、budget_exhausted 与源失败补记录；不能把未知目标或未通过窗口解析的任意模型字符串升格为可信范围。开始后失败纳入原 started/produced/failed 对账，准备阶段拒绝不伪装成成功，也不制造 query_unfinished。SDK 步数用完时，`finish_on_limit` 的现有判断须认安全巡检失败，复用已有无工具收尾；补“只有该失败、没有 produced、步骤用完”的正式 SDK 回归，固定说明不能丢失。

成功证据复用交付层本次已经完成权限校验的全部上下文记录，并按原执行轮次筛选，不仅看模型选入 blocks 的事实；不另读一遍 Evidence，不复制成功目标/窗口/计数到新类型。失败记录沿 `TurnRuns → TurnAnswer → PolicySession.commit_validated 的校验 → 交付` 传递；提交前从账本复制，轮末照常清理。手动请求沿现有请求 JSON 保存/读取与 ResultDelivery 重建；定时任务仍用已有独立 Session、run 状态和通知账本，不另保存一份完整回答或任务报告仓库。Session 提交校验携带可信记录，不等于把整个 TurnAnswer 再存进 SDK Session；Session 为实际可信失败对应的工具输出仅保存目标来源标记（工具由固定标记及原调用绑定），回放前复用交付层当前授权复核，仍向模型给无 Evidence 占位；不存失败原文/窗口/原因副本；审批暂停的原始 SDK RunState 则在恢复前复核既有账本中的失败来源，失败沿 action_requester_invalid 拒绝、不认领/执行动作。历史读取、外发和重发复核这些来源的当前工具/目标与接收许可、归属和期限，不能因为失败没有 Evidence 就省略边界；固定原因文本重新从码映射，不采信保存的模型原因说明。

### B5：短 Skill 与模型反馈

局部修改 `database_security.md`，不堆禁止条款：按工具固定码说明未完成原因；coverage 只说明其声明的读取/分类完整性，不保证晚到日志和规则无漏检。区分风险线索、未发现线索与未取得结果；覆盖不完整仍如实说明，但不改称“未巡检”，任务 completed 不证明覆盖完整。源失败也不自动定为数据库“异常”。分窗补查允许说明已取得的范围，固定提示仍准确引用原失败窗口。

已有超长/无法判定口径保持，补清 ERR 没有具体错误原因、多语句不提供业务用途。维护/ETL 只能是待核实可能性，不能从服务账号或状态推出。用户只要求建定时任务而相关工具不可用时，说明当前可用能力和配置缺口；不能擅自改成手动巡检或额外发送。仍允许用户随后明确要求手动操作，无新增通用查询禁令、澄清轮次或固定工具序列。

## 4. 新增限制及依据

| 检查/调整 | 具体失败场景及已有机制不足 | 作用范围 |
| --- | --- | --- |
| 缺审计表时一次刷新再复核 | 合法结构已经恢复，旧快照仍拒绝；后台刷新间隔不能保证当前调用看到恢复。 | 仅本工具、合法授权/预算之后；不循环、不让所有查询同步刷新。 |
| 明确源失败记账与 started 去向对账 | 只在 wrapper 返回字符串会让已开始查询失去去向，或被应用当 query_unfinished。 | 复用原账本，增加窄类型，拒绝与失败不造成功证据。 |
| 失败元数据在历史/外发时复核 | 没有成功 Evidence 的失败记录也会暴露目标/窗口；原成功证据复核覆盖不到新记录。 | 同原身份、目标/工具、接收与 TTL 边界，无新权限体系。 |
| 共享刷新隔离调用上下文 | 刷新的 SET 会污染触发者的 SQL trace，把审计 SQL 前繁忙误判为执行后失败。 | 仅共享刷新任务的 context；原并发共享、期限和治理规则不变，不全局放宽错误。 |
| 固定未完成前缀 | 模型已把缺表说成超时/内存、把未取得结果写成无风险；Skill 不能保证提示可见。 | 仅实际调用未取得结果；覆盖不完整沿覆盖行说明，不给其他工具增加前缀。 |

诊断日志不改变判定，失败后不自动重放、源权限、Evidence 和资源限额为既有边界，不另建防护层。
