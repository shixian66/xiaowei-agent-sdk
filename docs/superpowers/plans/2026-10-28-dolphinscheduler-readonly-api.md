## 2. 本期要完成的用户任务

用户看到的是诊断结论、关键事实、必要原文片段和限制。每次 DS 查询回答标明实际查询的环境（如“DS B：……”），多环境分开，空结果／失败也标明对应环境与状态，沿用现有来源和展示，不新建展示机制。工具调用、Evidence 编号或原始 API 响应不默认展示。以下四个问题就是固定任务集；后续可以补反例，不能用另一套更容易的标准替代。

| 编号 | 用户操作 → 系统行为 → 用户看到的结果 | 成功标准 | 不能接受的结果 |
| --- | --- | --- | --- |
| D1 | “查生产 A，昨晚订单项目有哪些失败工作流。” → 确认已选集群、项目及时间口径，按条件分页查询实例 → 返回失败实例、状态、时间和查询覆盖情况 | 区分工作流定义与一次运行；列表和数量一致；有剩余页或部分集群失败时明确说明；“昨晚”没有可信时间口径时先澄清 | 查询其他环境；把第一页当全部；把取消任务算失败；混淆失败实例数与工作流数；无权限说成不存在 |
| D2 | “这条失败告警是什么原因？” → 定位告警对应的工作流实例和任务尝试，读取／检索必要日志，按证据补上下文 → 说明失败节点、直接错误、原因判断及下一步 | 证据绑定正确集群、项目、实例和观察时刻；日志足够时给出具体错误，证据不足时指出具体缺口；区分直接错误与更深层推断 | 用最新成功运行解释旧告警；只看到 FAILED 就编造根因；只读尾部漏掉中间数据库报错；把脚本或日志里的文字当执行指令 |
| D3 | “这个工作流跑了 40 分钟，卡在哪？” → 查看实例、依赖、任务状态和时间，必要时查日志及可比历史运行 → 说明时间主要花在哪里、哪些已证实、还缺什么 | 区分排队／依赖等待／执行／重试；有可比基线才判断异常；存在充分证据时指出具体节点 | 将 40 分钟全部当数据库执行；凭历史平均值断言根因；没有数据库证据就说慢 SQL；把缺日志说成没有异常 |
| D4 | “刚才那个失败现在恢复了吗？” → 用原实例身份重新取数，并区分重试和后续新运行 → 给出各实例当前状态及观察时间 | 明确原失败实例是否改变、哪次重试或新运行成功；更新信息来自本次读取 | 把旧答案当实时状态；新实例成功就宣称旧实例成功；把任务实例 ID 相同当成执行尝试一定相同 |

日志足够却始终回答“无法判断”不算 D2／D3 通过。用户正常请求的完成质量，与只读、权限、容量等边界分别验收。

## 4. 多集群与只读边界

### 4.1 自然澄清与 DS 执行目标锁定

环境集合、提交时机及新读取约束只在 [ARCHITECTURE：DS](../../../ARCHITECTURE.md#dolphinscheduler-environment) 维护，§9 保留用户操作与可观察结果。Agent 从本轮请求、可信选择和本地目录理解意图；明确查询与仅提及的区别是工作方法，不能做成前置分类器或额外代码拒绝。

每套 DS 配置稳定且全局不冲突的 ID、名称／别名、用途／环境、版本、固定 API 根地址、凭据安全引用及服务时区。本地目录供澄清，不请求 DS、不靠远端项目搜索选环境；数量按列表扩展，3／6 套测试不变成数量禁令。

选择操作仅有 clusters 一个字段，SDK 严格 schema 负责拒绝多余字段；治理复用当前授权和预算。轮内结果写入可信 TurnRuns，应用已提交选择从会话元数据加载，具体提交接线见 §11.3。注入当前集合时，直接复用已有本地配置／权限核对结果，将已确认不可用的成员标注为“当前不可用”，集合不变；沿用现有可信选择提示，不另建可用性状态或远端探测。它不授予权限、不作业务 Evidence，也不属于 query 用途。与数据库共享 Agent 的 tools／instructions 有变化，仍须做数据库回归，不能只凭 Adapter 未改就宣称零影响。

### 4.2 确实需要强制落实的限制

只开放逐项核实无业务修改的端点；模型不能提交 URL、HTTP 方法、任意路径／请求体、凭据或原始文件路径。使用专用最小权限账号，按 DS 实际版本验证项目可见性及日志读取权限，不假设 Token 本身存在通用“只读”开关。

**HTTP GET 不等于只读。** DS 3.4.0 的 `GET /projects/{projectCode}/workflow-definition/{code}/versions/{version}` 会切换版本，不能拿来读取历史定义。精确端点清单、参数约束和测试负责强制只读；优先从实例详情取得该次运行的定义版本与 DAG，不用当前定义冒充历史执行配置。

日志／SQL／脚本是诊断数据，不授予执行权限；不得因日志要求重跑、下载脚本、变更数据库而执行。若确需调用现有数据库或监控诊断工具，仍按那些工具已有目标、用户意图和权限处理，不能从日志自动扩大目标或权限。

## 5. 建议工具范围

工具名与 schema 已按实现对齐现有风格。它们对两版 DS 提供相同业务语义，版本差异留在薄 Adapter；均显式包含 `cluster`。

下表列六项远端只读业务工具，加 §4.1 的本地选择操作。选择 schema 只有 clusters，普通内部函数留给开发，不做通用环境管理平台。

| 工具 | 适用问题、输入和结果限制 | 可修正错误或继续方式 |
| --- | --- | --- |
| `ds_list_projects` | 项目不明确时定位；关键词、页参数；获准项目 code／名称与分页覆盖 | I/O 前页参数可修正；成功空列表可换词或询问项目，不跨 DS 环境搜索 |
| `ds_list_workflow_instances` | D1、D3 历史对比、D4；project、可选定义 code、状态、绝对时间、页参数；实例身份、版本、时间及重跑字段 | I/O 前时间／分页可修正；按预算翻页。顶层实例范围、时间字段及截断须明示 |
| `ds_get_workflow_instance` | D2—D4；project、instance ID、可空 task_id、dynamic_sub_workflows 布尔值（仅 3.4.0 动态关联用 true）；有界 DAG、版本、按需的子运行／依赖运行依据，不默认给全部脚本或参数 | 同名可澄清；关联项目或依据缺失时补元数据／日志或询问，不按最新同名运行猜测 |
| `ds_list_task_instances` | D2／D3；project、workflow instance、任务名称／状态、页参数；任务类型、时间、尝试及归属 | 页参数可修正；区分定义 code 与实例 ID；不以有效任务列表冒充尝试历史 |
| `ds_read_task_log` | 补已知位置；完整任务身份、行范围及必要行内偏移；有限原文、位置、时间与覆盖 | 成功读取后在本轮缓存内改范围；超长行围绕命中补读。首次也走下载，不请求 detail |
| `ds_search_task_log` | D2／D3 未知位置报错；完整任务身份、字面关键词和命中／上下文上限；有限片段、位置、命中与覆盖 | 成功无命中可换词、补上下文；同轮自动复用。读取失败不可借换词重新下载 |

业务工具的目标与失败契约遵循 ARCHITECTURE。I/O 前参数错误返回现有闭集反馈；选择返回固定本地回执。各工具每个分支的 HTTP 次数须有固定上限，包含必要归属校验，不在工具内部循环发请求；列表一次只取模型指定页，翻页由 Agent 另传页参数。三个分页元数据列表每次 1 个 HTTP 请求，详情按下述分支计；日志最多 3 个（缺少可复用事实时依次核对运行、读取指定任务页、下载），有任务事实时只下载，缓存命中为 0。task_page_no 指定 100 条／页的任务所在页，不循环寻找；未在该页核实归属时返回缺口，不能说全局不存在。S3 详情无 task_id 为 1 次，有 task_id 的普通／依赖任务为 2 次、普通子关联最多 4 次（运行→有效任务→实际子关联→子项目范围详情核实）、3.4.0 动态子关联最多 3 次。不在一个工具里遍历子树，不从工具调用预算推导另一套 HTTP 计数器。

项目目录用于发现，不要求按固定顺序调用；已有可信实例定位即可直接查详情。业务时间统一为带时区的绝对时间，工具注明过滤的是启动时间等哪个字段；API 的包含端点语义在 Adapter 内规范化，不能把“昨晚启动”混为“昨晚失败”。时间口径不明先澄清。

日志工具执行前须核实任务属于该项目和实例。可复用本轮已验证且仍适用的任务事实；不能只信模型传来的 project，也不能假设上游每条带 project 路由都完整校验对象归属。重试可能更新同一 task ID 的字段或日志路径；结合重试字段、状态及观察时间确认是哪次尝试，旧日志取不到就明确缺口。

**按节点补证据：** 父工作流的子流程节点失败时，实例详情按该次父任务查询实际关联的子运行，返回可继续定位的集群／项目／实例引用及关系依据；Agent 再按需调用已有详情、任务和日志工具。每次补读仍受目标、对象归属、当前权限和预算约束，不按名称或最新运行猜关联，不自动遍历整张依赖图。关联不可获取时保留父节点已知状态并说明缺口。

D3 所需运行依据由详情工具按节点补充：3.1.8 的 dependentResult 是 JSON 状态映射，3.4.0 的 taskInstanceDependentResults 是运行上下文列表（含 projectCode／workflowDefinitionCode／taskDefinitionCode／dateCycle／dependentResult）；两者都只有状态，没有等待起止时间，不能代替历史尝试或证明时长。等待时长须从带时间的日志事件取证，两版分别构造实际协议夹具；静态 DAG 或总耗时减执行时间均不能单独证明等待原因。

返回列表保留已读页、总数（仅上游可信时）、是否有后续及必要筛选条件；上游和投影截断都要可辨认。详情中 DAG 最多 100 个节点／关系，指定节点即使不在摘要前 100 个也优先保留；仅节点版本与任务版本一致时附必要 SQL／脚本文本，每项最多 2048 字符且标截断。动态关联最多 8 个引用，超限明示遗漏，子项目仍需核实；不以成功响应掩盖内容缺失。

### 5.1 已核实的 API 事实

- **实例列表请求参数：** 3.1.8 路由 process-instances，定义过滤参数 `processDefineCode`；3.4.0 路由 workflow-instances，对应 `workflowDefinitionCode`。任务列表对应参数为 `processInstanceId`／`workflowInstanceId`；请求参数与响应字段分别映射。
- 3.4.0 实例列表 Mapper 排除子工作流且 searchVal 匹配实例名；D1 样例按顶层实例计数，工具如实说明覆盖，不把它称为含子运行的全量失败数。
- 工作流／任务实例查询支持名称、状态、时间、分页等条件，但这是**实例元数据过滤**，不是日志正文过滤。
- 日志提供 project 范围内的 `detail`（`taskInstanceId`、`skipLineNum`、`limit`）及 `download-log`。已查两版 Controller，未发现原生关键词搜索、按日志时间过滤或 tail 参数。
- 3.4.0 分页日志底层会限制返回内容，超长单行也会裁剪。因此请求 `limit=N` 却返回少于 N 行，不足以证明 EOF；响应 `lineNum` 也不是整份日志总行数。API 首段／下载会附加日志头，不能计为原文件行号。
- 两版实例详情服务按实例定义版本取得 DAG；仍需公司 API 响应校准。若某版或公司补丁未提供所需历史信息，返回缺口，不调用切版本接口补救。
- 两版实例路由均有 query-sub-by-parent，参数 taskId；两版 /{id}/tasks 都可返回依赖状态结果，但字段不同：3.1.8 为 dependentResult，3.4.0 为 taskInstanceDependentResults，不伪造同名字段。3.1.8 的 addDependResultForTaskList 读取 DEPENDENT 任务日志前段并填 dependentResult；该状态信息不含等待起止时刻，可能受前段日志可见性影响。按需接入现有详情工具，不增加子流程编排或依赖分析平台。

出处及版本见 §10；这些源码事实不是公司部署实测结论。

## 6. 10 MB 长日志如何处理

**10 MB 不应整份进入模型。** 推荐“有界原文读取 → 工具内确定性检索 → 少量原文片段 → Agent 判断并按需补读”。工具筛选没有第二个模型，也不预设每次必须查固定关键词。

### 6.1 单一下载路径与内部复用

1. **取得原文。** 两项日志工具首次需要该日志时，均用 httpx2.AsyncClient.stream／Response.aiter_bytes 有界接收项目范围的 download-log，不同时实现 detail 分页后端。只读几行也付一次下载成本；超限交付已证实片段与缺口，本期不同时解决任意大日志的低成本定点读取。实际任务需要该能力或下载负载不可接受时再评估替换路径。
2. **内部复用。** 按会话、轮次、集群、项目、工作流实例、任务实例及已验证尝试信息共用一份取样；尝试信息来自工具事实，不由模型填写。同对象并行调用也只下载一次。模型只传任务身份、关键词或位置，不接收／回传取样 ID，无同轮刷新参数。取样／失败状态轮末、取消、异常及审批暂停时释放，不跨轮缓存、不进 RunContext；本地补读仍核对权限与预算。暂停账本只保留已取日志身份及累计字节，恢复不能借内存释放重置额度或重复下载；原片段仍可引用，已释放的原文补读返回具体缺口，新一轮才重新采集。
3. **位置和时效。** 下载带人工日志头，去头后定义原文件行号；超长行返回行内位置并围绕命中补上下文。工具只解释已接收内容和采集时刻，客户端不能观察单次流中的源文件变化，完整接收也不证明源快照一致；下一轮重新取样，旧片段不冒充当前日志。
4. **Agent 自主补证据。** 可组合异常类、SQLState、错误码、业务词，换词或补读前后文；无 ERROR 或无命中不等于无异常。已有充分证据即可结束，不固定先看头再搜再读尾。缓存命中不发生 DS HTTP，失败后不能借换词重发。

### 6.2 建议初始预算与完整性语义

下表是待离线校准和公司验收的初始设置，不是当前生产配置或性能承诺。以本轮剩余预算和当前投影限额中更严格者为准，不增加全局模型／Session 容量。

| 资源 | 初始建议 | 到限行为 |
| --- | --- | --- |
| 单次日志接收正文 | 最多 16 MiB，受 HTTP 超时和本轮期限约束 | 停止接收，标明已读范围与未读后缀 |
| 一轮接收／缓存额度 | 合计 32 MiB，失败已收字节也计入；缓存复用不重复计下载量 | 达限停止新增取样；本地分析仍计调用数、期限和投影 |
| 接收／扫描期限 | 复用 HTTP 超时和本轮总期限，须覆盖接收与扫描；不另设固定 60 秒门槛 | 取消本次处理并说明不完整，不声称远端已停止 |
| 检索条件 | 最多 8 个字面关键词，可选大小写不敏感 | 允许换词，不建正则执行器或固定错误词库 |
| 单次日志投影 | 最多 16 KiB，含来源／覆盖，最多 8 个片段 | 说明省略／单行截断，返回可继续定位的位置 |
| 模型／Session／展示总容量 | 复用现有 Profile、Session、audience 投影及轮次／工具预算，不另加 48 KiB 日志配额 | 默认少量片段、按需补读，到限按现有路径结束，不扩大限额或伪称完整 |

每个工具按 §5 的固定 HTTP 上限执行，元数据响应也受现有响应大小与总期限限制。日志接收／缓存额度和模型／Session／展示投影分别计算；不新增按内部 HTTP 次数派生的轮内预算。

检索先按每个关键词保留少量代表命中及其前后文，再合并重叠片段，报告总命中数和实际返回数。有限代表不保证展示所有不同错误；有省略时返回继续定位线索，小维按更具体的异常类／错误码收窄，不能由“代表片段未见某错误”推出不存在。不得只截取日志开头或只保留最早的通用 ERROR；固定样例覆盖重复噪声淹没中间数据库异常的情况。

覆盖只返回已读字节范围、是否读到结尾和截断原因；发生接收／处理截断时明确未覆盖部分。命中数仅对完成检索的已读范围成立，不表示模型理解了全部内容或故障调查完成。

每段证据记录集群、项目、实例、任务、可得尝试／版本、采集时间、原文位置和覆盖说明；旧片段保留原时刻，下一轮重新解释位置，不拼成完整快照。

跨行异常保留前后文，验证 UTF-8、换行及超长行。整份日志仅在本轮临时内存，不入 Evidence、Session 或长期缓存，不建全文索引。持久化片段凭来源、位置和时间解释，不依赖已释放引用；遮蔽凭据不得悄悄改掉错误码和对象名，无法保留时说明受限。现有会话并发、每轮工具并发 4 和单轮 32 MiB 约束保留，进程容量仍需另计解码／索引开销；不另加 DS 信号量，公司观察真实源负载后再决定是否需要源级并发控制。

主线示例配置的模型请求上限为 1,000,000 字节、Session 历史上限为 400,000 字节，工具调用预算为 16 次。这说明不能把 10 MB 分批持续塞入对话；它们只是示例值，不代表公司当前配置。

## 7. 正常调用与关键失败行为

Agent 按已有线索定位运行、选择可疑节点、检索日志并补上下文，充分取证后结束，不固定调用顺序。失败分类、停止范围及轮次、继续调查与用户可见缺口仅遵循 [ARCHITECTURE：DS 读取失败](../../../ARCHITECTURE.md#dolphinscheduler-read-failures)；具体触发与结果见 §9，接线及兼容验收见 S1／S2，不另复制契约。

## 8. 本期做与不做

**本期建议做：** 3–6 套 DS 的静态只读 API 配置，两版必要差异，以上六项业务工具和 DS 本地选择操作，10 MB 级有界日志检索与上下文读取，D1—D4 的证据和失败表达，正式 Web／飞书入口上的同一任务体验。环境自然澄清与 DS 执行范围已确认，不扩大到数据库改造。

**本期不开发、不验收：** 重跑、补数、停止、上线／下线、修改定义、切版本等 DS 写操作；自动接收告警并触发诊断；替换现有 DS 告警程序；定时 DS 巡检；全平台血缘、日志长期归档／全文搜索平台、API 与元数据库双接入。它们只是后续范围，不因此新增提示词或代码中的禁止规则。现有功能也不因本期排除而移除。

需要强制禁止的仅为已说明的执行／数据边界：未获准写入、任意 API 透传、未授权目标或数据外发、执行日志指令。未来写操作按具体 Action 再设计和授权；本期不预建 DS 写框架、空审批接口或虚假的可执行 Action。

### 9.1 固定业务样例

以下数据为未来夹具的规格，不是本轮已执行的测试。实际 ID 可变，关系、正确结论和不能接受的结果保持。

- **D1：** 固定 Asia/Shanghai 的 20:00—次日 08:00 启动窗口；订单项目两页中合计两条失败实例，另有成功／取消实例；其他集群存在同名项目和重叠 ID。必须找全这两条、区分数量口径，既不串环境也不混入边界外记录。另加“未选环境”和“明确查两套但一套失败”变体。

- **D3：** 工作流已运行 40 分钟，其中上游依赖等待占 35 分钟，当前节点执行 5 分钟；存在成功历史运行。夹具必须提供与该次实例绑定的依赖等待开始、满足时刻，以及节点开始执行的运行记录或带时间日志，不能只提供“等待 35 分钟”的预制结论。必须据此指出主要耗时来自等待，不把 40 分钟归因于数据库。缺少依赖依据的变体只能说明节点执行前经过 35 分钟及待确认原因；另补确有数据库错误的运行中任务，检验能按新证据检索日志。

### 9.2 离线：接口、长日志和边界

在获准开发后，以真实 SDK 入口和可控 HTTP 协议响应覆盖两版路由／字段／业务 code、分页与时区、3／6 套配置和 ID 冲突、项目与任务归属、Token／权限拒绝、响应错误、Evidence 与接收范围。错误及拒绝路径断言没有未授权 I/O，特别覆盖 GET 切版本端点不能进入执行目录。

以 D1 的同项目不同工作流数据核对发出的过滤参数：3.1.8 为 `processDefineCode`，3.4.0 为 `workflowDefinitionCode`，结果不能因参数名被忽略而混入其他工作流。以 D2-C1 校验父任务到子实例的真实关系，再沿现有工具读取；D3-W1 的协议夹具提供实际可用字段或日志事件，分别验证依据充分和依据缺失，不能由测试直接注入派生结论代替取证。

DS 选择边界另外断言：无记录、目标不匹配、被撤权项零 DS I/O；部分撤权沿 D4-E3，集合不变。本地目录／选择不访问 DS，同一 SDK Loop 可接着完成原任务。选择只更新 TurnRuns，不能触发 query_unfinished；失败轮丢弃暂存，成功轮随 Session 提交，SDK／应用提交途中失败不可回放。新会话、取数后范围及数据库／历史路径回归沿 ARCHITECTURE；多余字段复用 SDK 严格 schema 的既有保证。受控输入不证明模型理解正确。

日志主夹具保留至少 10 MiB 中间错误夹在噪声里、超长单行、下载日志头、超限截断和下载超时。首部／尾部错误、CRLF／LF、UTF-8、跨行、多关键词、无 ERROR、错误正文和尝试变化只做离线检查；不测试客户端无法观察的单次采集源变化。删除分页后端专属测试，保留去头、位置和数据边界。

D2-L1 连续四次换词搜索及补读，断言同日志只下载一次、不调用 detail；内部缓存不串会话／轮次／任务，并行同对象不重复下载，结束／取消／异常释放。验证日志头与超长行定位，四次分析不因已删除的 48 KiB 门槛停止；仍受现有总预算约束，不强制真实 Agent 搜索四次。跨轮取样与任务重试仍保留，不新增模型引用错误或同轮刷新矩阵。

D1-F1／D2-F1／D4-F1 的离线检查只证明 Adapter 不自动重试、源停止按本轮生效、日志失败缓存不重复下载，以及仍获准独立事实／缺口的保存、展示和历史复核。单日志超时后同源元数据仍放行；未分类内部错误中止，不套用监控兜底。DS 说明使用配置名称，监控说明不变。Agent 是否换工具／参数重放由 §9.3 真实模型验证，脚本模型不能证明。另跑 TiDB／StarRocks 失败回归，DS 例外不外溢。

固定 10 MiB 成功样例应在建议单次读取及投影预算内完成，不能靠扩大模型请求限额通过。来源超出上限的反例允许不完整，但必须明确缺口。模拟协议只能证明客户端行为，不能证明 DS 服务端的实际内存、磁盘或网络负载。

### 9.3 获准真实模型：诊断能力

真实模型使用同一 D1—D4 和关键变体，经正式 Agent／治理链提供可控响应，记录工具选择、事实、依据、缺口、步数、耗时和用量。主套件用一版规范化投影；另一版必须做协议／公司校准，仅在 D3 等实际投影语义不同时补模型样例，不逐版本／集群重复整套评测。

| 同轮内部复用、日志失败不再下载（包括审批恢复） | 读／搜可能重复下载 10 MiB，SDK 可并行发工具，工具预算不辨别同一日志 | 仅 DS 同任务轮内缓存；并行复用、失败复用、轮末释放。不建通用等价请求引擎 |
| 有界节点／片段与覆盖说明 | DAG／日志可能远超可投影大小，真实片段不代表整份日志无其他错误 | 复用既有投影，新增 DS 字段与覆盖语义；不另加 48 KiB 总配额，不强制固定检索词或工具顺序 |

**取舍与备选。** 单一路径下载减少分页裁剪与双后端维护，代价是少量定点查看也下载；源负载或大日志任务超出初值时重评。保留读／搜两个清楚工具共享实现，避免模式参数变成万能接口。不提供定义目录工具：D1—D4／19 个变体没有消费者，D3 历史对比的定义 code 可从实例详情获得；按定义名定位有真实任务后再加，不能把实例名筛选说成定义名搜索。内部取样引用、同轮刷新、重复总配额与超时门槛均移除。以上是技术收敛，未扩大已批准的数据、目标、写入或重试权限；如需同轮跨集合、写操作、跨源自动换源或改变数据库语义，须单列产品取舍后确认。

### 11.5 切片与独立退出

依赖为 **S1 → S2 → S3 → S4**，每次只推进一个可验证结果。配置、空配置兼容、必要迁移和文档跟随实际消费者，不单独交付空框架。涉及公共治理／存储／SDK 接线的候选必须按精确 SHA 独立审查，再推进依赖切片；用户已授权功能实施与离线验证；真实模型、公司服务、合并及部署不在本轮执行范围。

#### S1：能选对环境、查失败与确认状态

- [ ] 落实可选配置、四项元数据工具、选择与 TurnRuns 暂存／Session 成功提交接线，接现有授权／治理／Evidence；原生 SDK 与可控 HTTP 验证同轮选择后继续。只做选择也应正常结束，不登记 query，不触发 query_unfinished。工具固定 HTTP 上限与按页调用有反例。
- [ ] DS 失败复用同一保存／历史／说明接口，但不能直接加入 MONITORING_READ_POLICIES。闭集原因及对象决定本轮停源或停对象，下一轮可重新读；单日志超时后同源元数据仍放行，未分类内部错误仍中止。DS 与监控混合失败区分来源，日志缺口带任务对象定位。DS 说明使用用户认得的配置名称，监控原文案／序列化不变。
- [ ] D1／D4、E1—E10 和 D1-F1／D4-F1 达标。B1 反例：已提交 A → 本轮选 B 并读取 → query_unfinished／回答校验失败／提交前取消 → 下轮“今天呢”仍用 A；成功提交才沿用 B。SDK／元数据提交失败不回放不一致历史。保留未选、错误参数、HTTP 200 业务失败、空结果、旧事实及新会话分支。
- [ ] A1-1：DS 轮内集合、消息关联及取数锁定状态能随 TurnLedger／RunState 序列化恢复；新记录往返不丢，升级前缺少新增字段的 JSON 在严格解析下使用缺省值，不使原有监控暂停失效。
- [ ] A1-2：同轮先读 DS、再触发现有监控审批暂停，恢复后仍使用原轮集合；集合外 DS 请求零 I/O，当前权限／Tool Scope 仍复核，不因恢复扩大权限或重置成会话旧选择。
- [ ] A1-3：暂停本身不更新已提交集合；恢复后的最终 commit_validated 按原 writing→active 路径一并提交选择。恢复后提交前失败保留原选择，提交途中失败仍不可回放，不自动重放工具。
- [ ] A2／C1／D4-E3：历史可回放时，B 撤权或配置移除走既有 not_allowed，零 I/O、不计 started、不留读取失败记录，A 仍能继续；模型只说明 B 当前不可用、不含业务事实。历史已有 B 不可读 Evidence 时按原边界提示新建会话。集合不变，不为此新增 _monitoring_failure_notice 权限例外或改共用交付复核。同片对照 D1-F1：源不可达／Token 失效必须留系统读取失败记录和缺口说明，不能并入 not_allowed。
- [ ] 真 PostgreSQL 验证迁移、提交成功／失败、重启恢复与历史／重发；群聊补 E6、D4-E2。DS 空／已配置分别回归数据库，3／6 套只测 DS；本期 automatic_tools 不含 DS，配置说明引用 §11.6，不新加拦截器。退出仅称元数据与选择离线通过。

主要影响 runtime.py、app.py、tools.py、governance.py、models.py、evidence.py、session.py／storage.py 及新增 DS 领域代码；不预定普通内部函数或拆分新目录。该片必须证明新数据路径真实经过治理，不能用孤立 Adapter 测试代替。

#### S2：10 MiB 中间报错能被定位

- [ ] 在 S1 之上接两项日志工具、单一流式下载和内部缓存，任务归属验证复用元数据；响应／单轮原文上限及失败状态只作用于 DS，不新增下载信号量。
- [ ] D2／L1 按同一数据定位中间 SQL 错误，换词补读仍只下载一次；保留直接错误与推断的区别。覆盖四次分析、长单行、跨行异常、无 ERROR、噪声、去头、Unicode、超限前缀及错误正文；整份日志不得进入模型、Session 或交付，必要片段按既有投影和来源规则处理。
- [ ] D2-F1 区分日志超时／Worker 不可达与 API 源建连失败：前者仍可查同源其他元数据，后者停该源本轮；检查并行同对象只下载一次、取消／异常释放与轮末清理。不存在模型取样 ID 或同轮刷新专属分支。
- [ ] S2 退出只断言 HTTP 次数及接收字节符合设计；峰值缓存／合成处理时间不列退出项。离线仅证明客户端行为，DS 服务端 10 MiB 负载仍待公司验收。

#### S3：能解释子流程失败和等待

- [ ] 按父任务实例关联真实子运行，普通子流程与 3.4.0 动态子流程分别核对只读映射，复用现有详情工具按需返回，不递归扫图。接口只返子 ID 时必须取得可核对的项目归属，不能把父项目当已证实的子项目。
- [ ] D2-C1 在旧失败子运行中找日志，后续成功运行不得替代；关联不可取或项目不明确时返回缺口／询问。公司任务类型影响哪一分支必须实测，不妨碍其他已校准分支推进。
- [ ] D3-W1 两版分别构造 dependentResult／taskInstanceDependentResults 实际响应：都只证明依赖状态；等待起止及 35 分钟来自带时间日志事件，节点执行 5 分钟来自对应运行记录。有效任务结果不替代历史尝试；移除时间依据后不能仅凭 40−5 判等待。
- [ ] 正常、关联缺失／跨项目、尝试变化、等待依据不足和运行中实际数据库错误分别通过；尚未校准分支列为未验收，不编造字段或预制结论。
