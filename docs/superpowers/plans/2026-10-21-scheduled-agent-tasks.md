# 多机器人通知与定时 Agent 任务实施计划

> **For agentic workers:** 实施时用 `superpowers:executing-plans`，按仓库默认串行完成当前切片。本轮只改本设计/计划，不开始功能开发。

**Goal:** 交付多个获准机器人通知、一次性提醒、通用独立 Agent 定时任务，再以 Node 核心巡检做首个真实业务验证。

**Architecture:** 同进程到期检查和现有 PostgreSQL；业务调查走 Application.run_turn/SDK Runner，每次新 Session。可信交付路径在治理后发送，后台 Agent 只见获准自动只读工具。

**Tech Stack:** Python 3.11、Agents SDK 0.22.3、SQLAlchemy/asyncpg、生产已有 httpx2；以实施时锁文件为准，不新增调度依赖、MCP Server、Worker 或 Loop。

**Spec:** [设计 v1.2](../specs/2026-10-21-scheduled-agent-tasks.md)。本计划 v1.2，2026-10-21；修订基线 `77dd5f316ac6a1a3fa0fdfbb901002a29885b03c`，产品基线 `691804424f8bf3ed04c32f806a291cfafa053266`。沿用设计 §3 的 U1–U7；本轮补足独立审查所指契约及用户已选择的执行/管理主体，不另复制需求清单。

## Global Constraints

- 当前只授权两份文档的静态核对/修改，不写功能、改配置/依赖/数据库、调用真实模型/公司源/Webhook 或部署。下列复选项均是未来获准实施的工作。
- 开发前按已批准修订同步 ARCHITECTURE 旧草案和根文档版本/审查索引；本轮不改根文件，不把旧审查结论当作 v1.2 已获批准。
- 单 Agent/SDK Loop、先治理再 I/O、Evidence/接收边界、独立 Session、有界预算、生产写逐次审批继续生效。用户确认规范化任务不授予其当前权限之外的能力。
- 每片只实现直接需要的状态及接口；A 不预建任务平台，B 不预建 Agent 运行字段，C 不写 Node 业务分派。普通函数及实现细节在开发时决定。

## Review Focus

- Agent 整理的合法任务可确认；获批版本 A 不能执行为 B，历史事实不因确认变成新 Evidence。B/C 负责。
- 同轮同机器人相同正文去重，不同且明确要求的正文可分别发送；超时后改字不得重发。事实与模型说明沿 feishu 投影分开，整轮失败不抹掉已接受回执。A 负责。
- 暂停/取消直接生效但仍核验管理权；task_control 不能恢复或执行生产写。B 负责。
- 成员核验失败只阻断当前业务/通知，下次重核；确定撤权持续停用。B/C 负责。
- 同目标密钥轮换不重批、不清空发送机会；实际接收目标变化必须重批。A/B/C 负责。
- 已占用发送机会在超时、崩溃、暂停/恢复或数据库备份恢复后不得自动重发；补执行只针对未开始的提醒。A/B 负责。
- Node 首次只验核心覆盖与指标，缺项不能称健康，IO/网络未做不能叫完整 U6 验收。D 负责。

## 1. 环境与依赖顺序

A → B → C → D，各自可演示、审查与验收。优先复用本仓库 Python 3.11/锁文件、正式 SDK 扩展点、既有配置及应用迁移。PG/审批/恢复测试用隔离 PostgreSQL；默认禁网，协议替身仅 loopback。固定样例的脚本模型只证明链路，真实模型及公司/机器人调用另获 Profile、范围与费用授权。

预计 A 一个 `src/xiaowei/webhook.py`；B 一个 `src/xiaowei/scheduled_tasks.py`；D 只有实际 MCP 结果不足时才补最小读取能力。保持简单函数与当前模块，不预建工厂或管理平台。下面的新测试文件均位于 `tests/sdk_core/`，是未来交付物，当前不存在；不把未来配置/命令写成已可用入口。

## 2. A：即时 Webhook 通知

**交付：** U1–U4；一个本地发送 Tool、静态机器人别名/安全引用、独立发送许可和最小 attempt 记录，包含获准 Evidence 摘要外发。

**影响范围：** 新 webhook.py、test_webhook_notification.py 和必要应用迁移；窄改 tools/governance/runtime/config/evidence/storage/app。此片不引入 job、调度器或任务控制。

- [ ] **先证明调用链并建立失败用例。** 真 SDK Runner＋脚本模型＋httpx2 MockTransport：正确别名/文字/获准摘要进入治理后只作一次 HTTP；未知别名、URL、用户/渠道/接收数据范围或 Evidence 不通过时零 HTTP。
- [ ] **实现最小闭环。** 按设计 §4 的 `(原 turn_id, 稳定机器人 ID, 规范化最终正文摘要)` 唯一键原子占用，时间戳/签名不进摘要；定时来源将按 occurrence 占用。真 Runner 验证同轮明确要求的两条不同提醒各一次，相同正文换 call_id/并发仍一次；同机器人准入串行，failed/unknown 后换字也不能自动再发。不接 requests resend，不把哈希变化当作新授权。
- [ ] **贯通内容和副作用回执。** 复用 feishu 投影的 validate_answer/Delivery 及既有事实/模型说明纯文本；容量按整行/块省略并明示，不新增 Audience。发送前代码收集回放加本轮全部模型可见 Evidence，并叠加机器人可接收范围。测试 accepted 后最终校验/模型/Session 失败，既有失败回执/状态仍显示已提交；unknown、暂不能读取回执不得冒称未发送。不额外开 API/CLI；必要窄改 channel/结果回执路径。
- [ ] **验证关键失败。** HTTP 200+业务失败、4xx/5xx、坏响应、写/读超时、取消和成功后落库失败分类准确；不同 call_id/并行/重启均不重复 POST。凭据哨兵检查模型、历史、Evidence、日志及最终回答；同目标可信轮换不重置 attempt，换接收目标仍拒绝旧许可。
- [ ] **检查、审查、交接。** 新用例及受影响治理、Evidence、runtime、飞书入口回归，相关 lint/type。冻结 SHA 独立审查许可、零未授权 I/O、响应及崩溃窗口；按实际结果更新 README/运维/handoff。真实 U1–U4 另获模型/测试机器人授权，API 接受与群内人工观察分开记。

**退出：** 即时文字与获准摘要的离线闭环和关键拒绝成立；没有真实模型/机器人则仅标离线通过。必要发送记录不能为“精简”删除；B 不依赖未解决的通知权限缺陷。

## 3. B：一次性提醒及直接停用

**依赖/交付：** A；新增最小获批任务定义、at 到期检查、固定提醒执行、状态查询、直接暂停/取消和重启恢复，不启动模型。存储只覆盖本片需要的 occurrence/发送关联。

**影响范围：** scheduled_tasks.py、test_scheduled_tasks.py、应用迁移；actions/runtime/app/channel 的必要接入、storage/session 的存储与保留。task_control 只用于本地暂停/取消，创建/恢复/扩大仍明确确认，不改监控 write 守卫。

- [ ] **先验证确认与直接停用的最小接入。** 真 Runner＋隔离 PG：Agent 草拟/整理规范化说明，用户看到最终日期/时区、文本、目标、迟到策略和预算，明确确认后一次激活。优先复用现有 ActionBinding/SDK 流程，获批定义版本独立于原 Session/Action 期限。另证有权用户一次调用可暂停/取消，不经过完整 Action；无权、后台或 task_control 请求恢复/创建/远端写均拒绝。若复用必须大改监控审批，停止重新定界，不建新审批平台。
- [ ] **实现并验证批准版本及依赖。** 保存不可变定义/批准版本、草拟时服务端冻结的全部模型可见 definition_evidence_ids、源 owner/channel/session 和数据截止；不建原文签名。创建/确认、定义展示、入模与发送都复用 Evidence 批量验证及接收范围。跨 Session 用服务器保存的源归属核验，不能把旧 ID 丢进新 Session 或只调单条 _checked。测试 10 天后转发 7 天 TTL 结果在创建时被拒绝、之后撤权/到期也不发；依赖为空的文字提醒可用。派生审批材料、Evidence、Session/缓存不能重新延长正文期限，过期隐藏/清理；已有通用 Action.status/record TTL 不自动覆盖此场景，必须证明本地窄适配可贯通，否则本片阻断。用户确认不等于数据 TTL 续期。
- [ ] **验证时间、权限与轮换。** 假时钟测一次性迟到窗口内补执行/窗口外 missed，管理员时区/首跑/次数/有效期默认值在材料中展示，不为已有值重复澄清。短暂成员核验超时/False 不授权也不永久停用；创建者及个人 grants 配置的管理员可直接停用，其他群成员即使知道 ID 也不能。暂停/取消与发送占用在同一事务比较 job 状态/版本。验证同目标轮换不重批/不清空 attempt，实际换目标须重批；确定静态撤权持续停用。
- [ ] **验证恢复并交付。** 新增并实测 scheduled_tasks.enabled=false（当前尚无该配置）：状态/停用可用，零后台模型/业务/通知 I/O。循环只在实例锁下启动恢复成功后运行，准入事务复用 InstanceLock.admits；丢锁不新开运行或占发送机会。原 Session 新建/到期不删无旧数据依赖的合法 job，依赖失效则禁用正文而不延长保留。重启仅补合法未开始提醒，started/unknown 不重发；备份隔离禁发、迁移/空配置及回退按现有维护框架验证。跑受影响 Action/SDK、存储、会话清理及渠道检查，冻结 SHA 独立审查，保留真实 U5 缺口。

**退出：** “整理→确认→持久化→到点一次发送→可查状态”及无重复审批的停止操作成立，暂时核验失败与确定撤权有不同可观察行为。迟到/预算配置值未定、激活或控制守卫未贯通时不开放真实任务。

## 4. C：通用独立 Agent 定时任务

**依赖/交付：** B/A；增加 interval、agent_task 的独立自动只读范围、运行记录与预算，每次通过正式 Application.run_turn 执行。后台 Agent 不拥有 notify；可信交付路径复用 A。

**影响范围：** scheduled_tasks/app/runtime、必要 RunContext 安全元数据、Evidence/Session 保留；新增 test_scheduled_agent.py。不另建权限来源、第二 Loop 或任务 DSL。

- [ ] **先做独立任务行为验证。** 真 Runner＋脚本模型＋隔离 PG，用两类合成只读任务/两个假时点验证新 Session、实际工具、Evidence/保存及共用 feishu 事实渲染/发送。固定提醒无模型调用；无旧依赖定义不受原聊天到期/清理影响，有定义依赖者必须在正文入模前按源归属/当前模型数据策略检查，失效不调用模型、不发送。不要把数据依赖的失效说成聊天任务平台不能独立运行。
- [ ] **实现并验证自主调查。** 在批准上界与当前工具/源/权限/预算交集内，Agent 可选工具、编写/修正查询和补证，达到事实/预算停止；必要信息不足报告未完成。当前参数/源失败按原契约处理，不把示例顺序变为业务 dispatcher。使用历史方法形成新定义可以通过，历史结论不能作为本次新事实。
- [ ] **验证授权及副作用边界。** 按用户选择以创建者＋原群授权运行，不借批准者；批准者事后仅失去审批 grant 不撤销旧 job，创建者失去当前读/通知权则停用。不能直接用 query scope：显式剔除其自动加入的 request_action_execution 及群内可见 propose，测试二者动态不可见、手工调用也在治理前置拒绝；同样拒绝 production write/approval、task_control 和 notify。SDK interruption 不 autoapprove。成员 partial/False/接口失败不执行且下轮重查，经授权状态显示连续未核实/末次成功和下一时点，安全日志可观察；不为报错绕权通知。发送复核本轮加定义相关 Evidence，失败不重跑。
- [ ] **验证计划与集成后交付。** 按锚点和周期迟到策略运行，同任务不重叠、不补历史；明确 busy 且模型/业务未开始时，一次性在窗口内再准入同一 occurrence，周期跳过，不新建机会。超时/已开始失败不得误归 busy 重跑。复用预算并验证禁用开关、恢复顺序及实例锁丢失阻断。跑受影响 app/SDK/治理/Evidence/Session/渠道回归，冻结 SHA 独立审查；真实 U7 的工具选择、事实、耗时/用量另获授权评估。

**退出：** 两类任务复用同一主链，证明未写死 Node；合法规范化任务可执行，生产写/未授权通知始终被拒绝。后续业务能力仍逐项验收，不宣称所有现有工具已获长期自动执行授权。

## 5. D：Node 核心巡检的首个业务验收

**依赖/交付：** C；首次先交目标覆盖/采集状态、CPU、内存、磁盘空间和一次结果通知。IO/网络、inode、复杂历史/持续判断不列为首次退出条件，也不能据核心通过关闭原 U6 完整目标。

**影响范围：** 先查实际 MCP 结果、现有结果模型/投影和协议用例；缺完整结构化数据才补同一源的最小读取及配置/治理，必要时窄 Node 方法说明。不在 scheduled_tasks.py 放指标公式或 Node 分派。

- [ ] **核实结构化数据缺口。** 对实际 MCP 版本/契约与源码 result:str、既有官方 v0.18.0 歧义反例逐项核对；若仍同版同契约，复用已有证据，不重复无意义调研。若实际可保真返回完整 labels/type/values/time/warnings/覆盖，则验证并复用；否则才补最小受治理 Prometheus 读取。公司 API 可达性/认证及同源性另获授权后确认，不能猜解析现有文本。
- [ ] **定义核心口径并验证可手算样本。** Node 目标分母包括 down/缺数据实例，确认实际 job/labels，CPU 使用窗口、内存和磁盘单位/必要过滤；健康、异常、采集不可用、缺测/重复、NaN/Inf、warnings/截断和预算不足分别产生正确事实/未检查说明。无需先建设15分钟持续判定或 IO/网卡速率模型。
- [ ] **验证完整核心任务。** 用 U6 的原请求做“确认核心范围→两个独立时点重新取证→一次通知”的离线正式 SDK 链路；用户结果明确 IO/网络未纳入，缺项不能说全健康。Agent 可在获准源补证，Node selector 只做业务覆盖，不建指标白名单。自动修复/重启拒绝；另一个只读任务仍能复用调度。
- [ ] **检查并分项真实验收。** 受影响协议/指标/查询/飞书/审批回归和阶段所需 lint/type/CI 检查按冻结 SHA 记录。获准实际模型、Prometheus 和测试机器人后验证核心值/覆盖及 API/群内表现，分别记离线、模型、源、发送、部署/用户接受。根据实测价值再提出 IO/网络后续范围，不为预期未来能力预建组件。

**退出：** D 核心用例实际可用、限制准确；真实环境未测则只交离线核心。完整 U6 的 IO/网络仍开放，下一步由实测和产品取舍确定。
