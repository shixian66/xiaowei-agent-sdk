# 多机器人通知与定时 Agent 任务实施计划

> **For agentic workers:** 按 `superpowers:executing-plans` 和仓库规范串行完成当前切片。用户已授权实现、测试及常规修复，当前先实施 A；不同时展开后续片。

**Goal:** 交付多个获准机器人通知、一次性提醒、通用独立 Agent 定时任务，再以 Node 核心巡检做首个真实业务验证。

**Architecture:** 同进程到期检查和现有 PostgreSQL；业务调查走 Application.run_turn/SDK Runner，每次新 Session。可信交付路径在治理后发送，后台 Agent 只见获准自动只读工具。

**Tech Stack:** Python 3.11、Agents SDK 0.22.3、SQLAlchemy/asyncpg、生产已有 httpx2；以实施时锁文件为准，不新增调度依赖、MCP Server、Worker 或 Loop。

**Spec:** [设计 v1.4](../specs/2026-10-21-scheduled-agent-tasks.md)。本计划 v1.4，2026-10-21；基于 v1.3 定稿 `71398cf8e7f076e6bc3c840a6566ca49a7709f00`，产品基线 `691804424f8bf3ed04c32f806a291cfafa053266`。沿用设计 §3 的 U1–U7；保留对 v1.2 复审的四项验收，并落实 A 实现审查，不另复制需求清单。

## Global Constraints

- 当前授权产品实现、离线测试和常规修复，使用独立分支与隔离测试存储；A 复审通过后已获推送、开 PR 及检查通过后合并授权。真实模型/公司源/Webhook和部署仍未授权。下列复选项按实际证据完成，脚本模型不证明自主能力。
- ARCHITECTURE 已按批准修订同步产品边界；对 v1.2 的审查不替代实现候选的独立审查或真实验证。
- 单 Agent/SDK Loop、先治理再 I/O、Evidence/接收边界、独立 Session、有界预算、生产写逐次审批继续生效。用户确认规范化任务不授予其当前权限之外的能力。
- 每片只实现直接需要的状态及接口；A 不预建任务平台，B 不预建 Agent 运行字段，C 不写 Node 业务分派。普通函数及实现细节在开发时决定。

## Review Focus

- Agent 整理的合法任务可确认；获批版本 A 不能执行为 B，历史事实不因确认变成新 Evidence。B/C 负责。
- 同轮同机器人相同正文去重，不同且明确要求的正文可分别发送；超时后改字不得自动重发。unknown 后下一轮用户明确重发须已展示重复风险，才可占新机会。事实与模型说明沿 feishu 投影分开，整轮失败不抹掉已接受回执。A 负责。
- 暂停/取消直接生效但仍核验管理权；task_control 不能恢复或执行生产写。B 负责。
- 成员核验失败只阻断当前业务/通知，下次重核；确定撤权持续停用。B/C 负责。
- 同目标密钥轮换不重批、不清空发送机会；实际接收目标变化必须重批。A/B/C 负责。
- 已占用发送机会在超时、崩溃、暂停/恢复或数据库备份恢复后不得自动重发；补执行只针对未开始的提醒。A/B 负责。
- Node 首次只验核心覆盖与指标，缺项不能称健康，IO/网络未做不能叫完整 U6 验收。D 负责。
- U6 带旧证据起草可能数小时后、至多示例保留期7天就失效，确认必须展示精确截止与无旧依赖的创建办法；不能只测试空白历史。B/C 负责，D 沿用。

- [x] **实现最小闭环。** 按设计 §4 的 `(原 turn_id, 稳定机器人 ID, 规范化最终正文摘要)` 唯一键原子占用，时间戳/签名不进摘要；定时来源将按 occurrence 占用。真 Runner 验证同轮明确要求的两条不同提醒各一次，相同正文换 call_id/并发仍一次；同机器人准入串行，failed/unknown 后换字也不能自动再发。不接 requests resend，不把哈希变化当作新授权。

- [x] **验证关键失败。** HTTP 200+业务失败、4xx/5xx、坏响应、写/读超时、取消和成功后落库失败分类准确；不同 call_id/并行/重启均不重复 POST。凭据哨兵检查模型、历史、Evidence、日志及最终回答；同目标可信轮换不重置 attempt，换接收目标仍拒绝旧许可。
- [x] **检查、审查、交接。** 新用例及受影响治理、Evidence、runtime、飞书入口回归，相关 lint/type。冻结 SHA 独立复审本次修复、许可、零未授权 I/O、响应及崩溃窗口；按实际结果更新 README/handoff。真实 U1–U4 另获模型/测试机器人授权，API 接受与群内人工观察分开记。

**已确认限制与新增验收：** 审批恢复轮不提供通知工具，准备/等待批准材料必须由代码提示“批准后不会自动通知，完成后请另发通知要求”。真 Runner/正式入口验证审批仍正常执行、恢复轮零 Webhook POST、随后普通群请求可按原授权通知。风险提示按原群＋稳定机器人共享，覆盖 A 未展示警告时 B 的发送也被拦截，以及警告送达后明确重发成功；容量预览父交付失败不能解除门槛。接收授权可显式配置实际 SDK 执行请求证据工具，不隐含授予写权或数据接收权。

**状态（2026-10-22）：按 52f7b0e 独立审查修复 B1/C1/N1–N3；离线验证与精确版本复审结果见 handoff §5。真实 U5 尚未验收，未开放生产。**

- [x] **实现并验证批准版本及依赖。** 保存不可变定义/批准版本、草拟时服务端冻结的全部模型可见 definition_evidence_ids、源 owner/channel/session 和数据截止；不建原文签名。普通轮次在工具入口实时调用现有 replayed 回调，再合并本轮可见证据，仅审批恢复沿用 ctx.evidence_ids。必须用真 Runner 测历史已回放而 ctx.evidence_ids 为空时草案依赖仍包含历史证据，不能只测空会话。创建/确认、定义展示、入模与发送都复用 Evidence 批量验证及接收范围。跨 Session 用服务器保存的源归属核验，不能把旧 ID 丢进新 Session 或只调单条 _checked。测试 10 天后转发 7 天 TTL 结果在创建时被拒绝、之后撤权/到期也不发；依赖为空的文字提醒可用。派生审批材料、Evidence、Session/缓存不能重新延长正文期限，过期隐藏/清理；已有通用 Action.status/record TTL 不自动覆盖此场景，必须证明本地窄适配可贯通，否则本片阻断。用户确认不等于数据 TTL 续期。

- [x] **验证恢复并交付。** 新增并实测 scheduled_tasks.enabled=false（已实现，默认关闭）：状态/停用可用，零后台模型/业务/通知 I/O。循环只在实例锁下启动恢复成功后运行，准入事务复用 InstanceLock.admits；丢锁不新开运行或占发送机会。原 Session 新建/到期不删无旧数据依赖的合法 job，依赖失效则禁用正文而不延长保留。重启仅补合法未开始提醒，started/unknown 不重发；备份隔离禁发、迁移/空配置及回退按现有维护框架验证。跑受影响 Action/SDK、存储、会话清理及渠道检查，冻结 SHA 独立审查，保留真实 U5 缺口。

**本次契约与验收：** 分别批准的提醒不调用即时 unknown 风险门槛；先 unknown 的提醒仍不重发，第二个已激活提醒正常发送，其 unknown 仍阻断即时发送直至提示实际交付。批准必须早于 run_at；在激活事务内达到或超过时间则确定拒绝，Action 状态与群回执说明未激活。迟到窗口只补已激活且未开始的任务。发送截止与最早数据 TTL 分开，测试带七天历史＋近时提醒，越过发送截止清理后仍可回放历史；数据到期仍隐藏/清理。暂停/取消与 claim 并发、恢复 reason=response_unknown 同样回归，并对期限和门槛做隔离变异。

**实现说明：** B 只提供起草、确认激活、已知 ID 状态查询、暂停/取消；恢复/编辑/列表留待有直接需求的切片，不预建通用管理层。到期无模型；复用现有 SDK interruption/RunState/ActionBinding 和原群审批。新增 ActionBinding 的薄接入冻结实时 replayed＋本轮 Evidence，批准版本对应独立 job。状态管理走窄 task_control，未知风险复用 A 的关键回执交付。schema14 在通知表增加唯一 job 关联，不另建投递系统。默认值及权限以 ARCHITECTURE 为准；代码与验证快照见 handoff。

**退出：** “整理→确认→持久化→到点一次发送→可查状态”及无重复审批的停止操作成立，暂时核验失败与确定撤权有不同可观察行为。迟到/预算配置值未定、激活或控制守卫未贯通时不开放真实任务。

**依赖/交付：** B/A；增加 interval、agent_task 的独立自动只读范围、运行记录与预算，每次通过正式 Application.run_turn 执行。后台 Agent 不拥有 notify；可信交付路径复用 A。

**影响范围：** scheduled_tasks/app/runtime、必要 RunContext 安全元数据、Evidence/Session 保留；新增 test_scheduled_agent.py。不另建权限来源、第二 Loop 或任务 DSL。

- [ ] **先做独立任务行为验证。** 真 Runner＋脚本模型＋隔离 PG，用两类合成只读任务/两个假时点验证新 Session、实际工具、Evidence/保存及共用 feishu 事实渲染/发送。固定提醒无模型调用；无旧依赖定义不受原聊天到期/清理影响，有定义依赖者必须在正文入模前按源归属/当前模型数据策略检查，失效不调用模型、不发送。不要把数据依赖的失效说成聊天任务平台不能独立运行。
- [ ] **验证 U6 期限体验。** 在已有旧查询 Evidence 的共享群 Session 提出原 U6：断言历史依赖非空，确认材料按最早依赖/配置截止写明“本任务将于 X 时失效”及原因，不承诺数周运行。再走用户显式 `/新建` 后完整重述、起草前无业务查询的路径，断言无旧依赖且不受旧数据期限限制；须提前说明 `/新建` 轮换全群上下文，不自动切换、不复制旧草案。任务仍受配置有效期/权限/预算约束。如该操作频繁妨碍正常使用，按设计 §4 评估隔离起草；不为此给 A/B 增加前置模型调用。
- [ ] **实现并验证自主调查。** 在批准上界与当前工具/源/权限/预算交集内，Agent 可选工具、编写/修正查询和补证，达到事实/预算停止；必要信息不足报告未完成。当前参数/源失败按原契约处理，不把示例顺序变为业务 dispatcher。使用历史方法形成新定义可以通过，历史结论不能作为本次新事实。
- [ ] **验证授权及副作用边界。** 按用户选择以创建者＋原群授权运行，不借批准者；批准者事后仅失去审批 grant 不撤销旧 job，创建者失去当前读/通知权则停用。不能直接用 query scope：显式剔除其自动加入的 request_action_execution 及群内可见 propose，测试二者动态不可见、手工调用也在治理前置拒绝；同样拒绝 production write/approval、task_control 和 notify。SDK interruption 不 autoapprove。成员 partial/False/接口失败不执行且下轮重查，经授权状态显示连续未核实/末次成功和下一时点，安全日志可观察；不为报错绕权通知。发送复核本轮加定义相关 Evidence，失败不重跑。
- [ ] **验证计划与集成后交付。** 按锚点和周期迟到策略运行，同任务不重叠、不补历史；明确 busy 且模型/业务未开始时，一次性在窗口内再准入同一 occurrence，周期跳过，不新建机会。超时/已开始失败不得误归 busy 重跑。复用预算并验证禁用开关、恢复顺序及实例锁丢失阻断。跑受影响 app/SDK/治理/Evidence/Session/渠道回归，冻结 SHA 独立审查；真实 U7 的工具选择、事实、耗时/用量另获授权评估。

**退出：** 两类任务复用同一主链，证明未写死 Node；合法规范化任务可执行，生产写/未授权通知始终被拒绝。后续业务能力仍逐项验收，不宣称所有现有工具已获长期自动执行授权。

## 5. D：Node 核心巡检的首个业务验收

**依赖/交付：** C；首次先交目标覆盖/采集状态、CPU、内存、磁盘空间和一次结果通知。IO/网络、inode、复杂历史/持续判断不列为首次退出条件，也不能据核心通过关闭原 U6 完整目标。

**影响范围：** 先查实际 MCP 结果、现有结果模型/投影和协议用例；缺完整结构化数据才补同一源的最小读取及配置/治理，必要时窄 Node 方法说明。不在 scheduled_tasks.py 放指标公式或 Node 分派。
