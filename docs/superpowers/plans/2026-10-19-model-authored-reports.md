# 模型自主 HTML/MD 报告最小开发方案

> 状态：R0/R1/R2 离线实现、完整回归和独立复审已完成，可供本地审阅；R3 按用户决定留待公司内网验证，未验收。日期：2026-10-19，Asia/Shanghai。代码基线：`b89d4ee71cb5082adcde396f3dece12fd169af48`；开发分支 `codex/model-authored-reports`。未调用真实模型或公司服务，未部署。
>
> 已按用户连续开发授权串行推进，采用 `superpowers:executing-plans` 与 TDD；高风险差异须针对具体候选版本独立审查。真实 Profile/数据/预算仍须明确授权，本文件不将离线通过晋级为真实能力验收。

**目标：** 用户要求报告后，同一个 Agent 自主调查，通过现有有序文字/事实块编写自然 Markdown 或自行设计的静态 HTML 报告；报告 Skill 改善调查、叙事和设计质量，小维保留授权、可信事实、安全处理与完整交付。

**架构：** 复用 `AgentAnswer.blocks`、`report_format`、`awaiting_user`，改变显式报告的文字块渲染方式；代码在模型选择的位置填入可信事实。复用 SDK Runner、Session、原请求和飞书分项交付，不新增正文或摘要字段、文件工具和另一套运行循环。

**技术栈：** Python 3.11、Agents SDK 0.22.3、PostgreSQL/SQLAlchemy、现有 `markdown-it-py` 和渠道 SDK；报告锁定 `nh3 0.3.7` 与 `tinycss2 1.5.1`。已验证独立环境安装、Linux amd64 二进制包安装和报告 wheel 包含 Skill；浏览器行为证据见 §9，不代表真实 provider 已验证。

**来源：** [当前架构](../../../ARCHITECTURE.md#result-delivery)、[当前交接](../../../AGENT_HANDOFF.md)、[S3 自由回答结构计划](2026-10-17-free-answer-structure.md)及本次会话方向。本文是后续报告切片提案，不覆盖 S3 已确认契约；实现时只更新获准且受影响的架构条目。

## 1. 用户结果与方案选择

示例任务：“巡检我选定的 StarRocks 环境，结合获准的监控源，生成深色科技风 HTML 报告，包含发现、分析与建议。”Agent 自行选择调查顺序、章节、风格和事实块位置；缺少必要环境或口径时才澄清，已有可信上下文不重复询问。报告格式不扩大查询权限，也不自动执行建议。

用户收到关联原请求的可读简短预览与完整附件。附件按模型块顺序交错排列分析和代码事实，关键结论附近可以核对实际 SQL、结果、来源及限制。章节不由程序固定拼装，程序也不预设 KPI 组件。

| 方案 | 判断与取舍 |
| --- | --- |
| **复用现有 blocks（采用）** | 改文字渲染，保留事实位置、既有保存和分卷链路；不增加模型输出字段和重复正文。代价是每个 HTML 文字块是独立片段，Grid/Flex 不能跨越代码事实章节，系统事实样式仍由代码控制 |
| 新增独立 `report_document`（本次不采用） | 更适合一体化模型正文，但增加回答/兼容/预览契约，且正文与事实集中分开时核对更困难。只有独立片段无法通过既定视觉样例时才重新比较，不能提前扩展 |

首版接收 HTML 片段和受限内联 CSS，安全外壳由代码生成；这是减少样式作用范围的实现取舍，不是“内联样式天然安全”的结论。模型可以设计片段内的标题、布局、颜色、字体和表格；模型复述的数值仍属于模型说明，不能取得系统事实身份。

单个文字块不可拆，块与块之间可分卷；事实继续按整章节或整行拆分。一个文件仍最多 400,000 字节。该值是文件容量，不是承诺模型能一次生成的正文规模。

SQL 大结果的行数、字节和单值限额调整暂缓。本次不新增 Shell、任意代码执行、通用模板/组件平台、公式 DSL、独立报告数据库、Web 下载入口、监控曲线、PDF 或交互图表。

## 3. 回答契约、预算与失败行为

模型输出字段保持现状：

```text
AgentAnswer
  blocks          有序 TextBlock | FactBlock
  report_format   md | html | null
  awaiting_user   原有等待用户声明
```

### 3.1 报告模式与渠道

- 用户明确要文件、`report_format` 非空且 `awaiting_user=false` 时，飞书附件文字块按对应格式处理；每个片段自行闭合，不能借前后文字块跨过事实块形成一个 HTML 容器。显式模式取原 `Delivery.report_format`，不能在自动附件补齐默认 `md` 后把所有附件误判成显式报告。
- 普通消息及超容量自动转附件继续沿现有文字展示，不因其中出现 `<div>` 就自动解释 HTML；不能用正文字符猜测用户是否要求报告。
- `awaiting_user=true` 继续交付普通消息，不因预填格式生成文件。Skill 要求此时写普通文字，必要澄清不承受生成报告的成本。
- Web 仍无文件入口；不把 HTML 当聊天 DOM 注入。明确文件请求按现有“不支持文件”规则交付，可提示使用飞书，不额外运行模型或查询。
- 旧 Legacy/v2 按现有严格解析保留；已绑定附件/消息重发使用原字节。**A2：源码已确认“回答保存成功、附件尚未绑定”窗口可达**：`ChannelStore.complete` 保存回答，后续飞书准备阶段才调用 `bind_delivery_parts`。升级后的首次投递或未绑定字节的恢复必须纳入 R0/R1，不把它当作不存在的旧路径。
- 旧纯文本不能因新 HTML 解析语义而无声丢字。R0 用含 `a<b`、`<table> 很慢`、SQL 和代码围栏的旧记录重现该窗口，确定新旧报告语义如何区分；优先评估现有可信保存版本，核对版本经过请求读取、`TurnAnswer` 重建和 `Delivery` 后不会丢失。需要时只补最小应用侧版本区分，不靠正文猜格式，也不改变 provider 的输出 schema。结论先写明再实施；未解决前不开放受影响的 HTML 路径，不阻断不依赖它的 MD 工作。

### 3.2 文字预算与真实输出能力

普通模式保留 16,000 字节/64 块。报告初始也沿用该既有预算，不先另拍较大数字或增加配置项。R0 以代表性 MD/HTML 样例检查预算是否妨碍目标；不足时只提高报告模式的累计文字预算，并写明样例大小、调整依据和主要成本。澄清及普通自动附件不因此放宽。

以下约束分别成立，不能互相替代：本地累计文字预算、Profile 输出 token/响应字节/期限、回答保存容量、Session 回放容量，以及带外壳/来源后的单文件容量。附件分卷不会让一次模型调用输出更多 token。

已有示例 Profile 的 `max_output_tokens=16384` 只证明配置值，不证明能生成多少中文或 HTML。内联样式和 JSON 转义均有成本；实际字节与 token 比例、Gemini 思考 token 是否计入上限，须按获准的具体端点/模型核实。真实 Profile 可用时在 R0 尽早测典型报告；无授权时先用合成材料验证离线路径，保留真实长度/质量缺口，不阻断不依赖它的实现，也不宣称预算足够。

### 3.3 失败分类

- **完整回答后的结构、引用或本地文字预算错误：** 复用现有一次无工具改写；若报告预算调整，同步首次校验与改写提示，不能仍要求报告缩回普通预算。不能把所有文件容量/渲染失败都归入该处理器。
- **上游 `MAX_TOKENS` 或其他非完整终态：** 当前会在响应边界拒收，不进入 `invalid_final_output`。保留终止行为，不改写、不续写、不重查；首版的用户提示取舍按下面 A1，不新增重试循环。
- **安全处理或文件准备失败：** 按 §5.1 区分正常规范化、带说明交付与明确失败，不把所有清理差异交给改写。不可分块放不下时不裁半段，不缩减事实凑容量。
- **Evidence、未完成执行、保存或投递失败：** 沿现有分类阻断相关结果，不重新运行业务工具，不以部分送达声称整体完成。

正文按原最终回答路径进入 Session，仍受实际字节与期限限制；不另建文档仓库或隐式裁剪历史。

**A1 的首版取舍：保留现有通用失败回执。** 当前细分拒收原因用于日志；正式渠道通过 `TurnReason → FailureCode → 保存记录 → 固定回执` 交付失败，`TurnError` 的自定义文字不会直接透传。仅改 `app.py` 文案不足以让飞书显示“回答超出输出上限”。为保持本次范围最小，首版不扩充失败码，不承诺自动建议缩短；用户暂不能从通用回执区分截断、超时和其他模型失败。README/排障说明可指导操作者根据固定日志原因确认输出超限，再建议缩短或拆分请求。

R1 增加正式渠道回归：合成 `MAX_TOKENS` 后仍是既有固定回执，无上游原文泄露、改写、续写或业务工具重跑。若之后确需专门提示，须贯通应用分类、存储失败码和渠道回执并验证持久化/重启后的行为，不以局部异常文案检查代替；此项为后续体验取舍，不是首版隐含完成项。

## 4. 事实、预览与分卷怎样交付

### 4.1 分清身份，保留就近位置

报告按当前 blocks 顺序排列文字与代码事实，其余结果沿现有规则补全。文件头给出模型内容/系统事实的简短图例，各模型片段由代码标记来源身份；不为每个文字块反复添加同一章节标题，不把整篇标为“已核实”。关键结论附近是否选择了适当事实块由任务样例评估，代码不声称能验证任意自然语言结论。

可信值、实际 SQL/DDL、表格、来源、目标、采集时间、分页与截断说明只取当前 `Delivery` 的获准事实。需交付查询结果漏引继续补全；诊断、DDL、discovery 等仍按现有显式引用规则展示，不导出整个上下文或会话。动作与审批材料继续置顶且不进报告。

模型可以复述数值、制作自己的表格，但它们仍是模型说明。Prometheus 文本结果原样保留，不猜成可信 KPI 或推断单位/窗口。无事实的一般解释允许直接成文档，不为凑报告发起查询。

### 4.2 主消息不泄露 HTML 布局源码

HTML 报告的预览从同一次准备所得的安全片段提取可读文字，优先使用标准库 `html.parser`，段落/列表保留合理分隔，再进入现有飞书渲染器；不直接把 `<section>`、`style=` 等布局源码当摘要，不为文字提取新增依赖。有意展示的 HTML/SQL 示例仍作为文字保留，不能用“禁止出现尖括号字符串”误删代码内容。MD 优先复用现有可读预览。无需新增摘要字段、要求固定的第一个摘要块或再调一次模型。

预览仍保留代码说明、必要范围/失败信息和动作/事实保护；原报告块不会被纯文本预览覆盖。明确这是预览，完整内容见附件。不能为了省预览空间隐藏撤权、截断或未完成交付说明。

### 4.3 原链路保存与恢复

最终提交、历史读取、首次发送和重发复用现有 Evidence 边界，复核全部可见证据，不只验证显式引用。Session 与 Evidence 不要求相同保留期；只要相关证据过期或撤权，已有回放/历史边界应阻断相关内容，不能仅删工具结果却继续回放其模型解释。

每次投递尝试开始完整复核一次，后续沿现有有效期、readiness、owner/attempt 检查，不恢复同一状态下重复完整 ACL 校验。HTML 事实值仍逐值转义，MD 事实仍保真表格/围栏，均不经过模型片段清理器。

文件继续由 `build_reports` 按块、完整章节或事实整行分卷。各卷保留自己的来源与必要限制、顺序标记；分卷可能分开结论与依据，须能靠结果编号核对。模型文字块不可拆，超限明确失败，不引入自动语义切割。

`xiaowei_delivery_part` 继续保存首次准备的不可变文件和消息字节、键及回执；重发不重新生成、调用模型或查数，上传未知禁止重传。当前安全策略不再允许交付旧文件时阻断并说明，不清洗改写后冒充原字节。不为本方案新增数据库或每轮文件总量预算。

## 5. 最小文档安全边界

### HTML

- 用成熟清理库解析、规范化每个独立片段；外壳、CSP、来源标签、事实区域与导航由代码生成。模型不能控制这些容器及祖先的属性。
- 首版允许标题、段落、列表、布局、代码、表格等静态标签；模型不能提供 `html/head/body/style/meta/base/script/link/iframe/object/embed/form`、SVG/MathML、媒体、图片和事件属性等活动或资源入口。
- 只开放受限内联 `style`，不保留模型 class/id/data、任意选择器。起始范围为颜色/背景色、字体、对齐、间距、边框/圆角/阴影、宽度及 Flex/Grid 基本布局；不开放定位、层叠、变换、过滤器、生成内容、动画、CSS 变量及资源加载属性。
- 候选 `nh3` 的属性名列表与语法规范化不等于 CSS 值安全。R0 覆盖负间距、巨大尺寸、`url()`、`expression()`、`!important`、异常嵌套和未闭合标签，按具体反例确定必要值约束；不自行扩成 CSS 引擎。
- 代码控制的片段容器需证明不会越界遮挡事实；`contain: paint` 是候选措施，不限制内容高度，也不单独证明安全。首版不默认设置固定高度的内嵌滚动；用值约束、容器和代码导航解决具体问题，验证桌面、窄屏及打印完整性，失败则调整并复审。
- 内联样式减少作用域，但会重复消耗 token，也限制全局主题/媒体查询。样式重复比例或视觉样例不达标时重新比较更小替代，不偷偷退回固定正文模板，也不宣称任意 CSS 已支持。
- CSP 禁止脚本、外部/本地资源、对象、表单和额外框架请求，作为补充边界。用真实浏览器网络记录验证无未授权 I/O；不靠结束标签、类名前缀、正则或 `cleaned == source` 宣布安全。
- **A2 的新内容规则：** Skill 要求显示为普通文字的 `<`、`&` 及 SQL/尖括号片段在 HTML 文本节点中正确转义，代码示例使用转义后的 `pre/code`。R2 覆盖 `a&lt;b`、`&lt;table&gt; 很慢`、`&amp;`、SQL 比较与标签样文本，核对附件和预览都保留目标文字；另测未转义反例，不声称解析器能猜出任意模型字符串原本想表达的文字。旧记录不依赖新 Skill 补救，按 §3.1 的可信语义区分处理。

### Markdown 与共享处理

模型可用标题、段落、强调、列表、代码围栏和表格，不再把全部文字套入代码围栏。复用现有解析器处理明确静态子集；原始 HTML、图片和链接不能变成可执行或自动加载内容，代码围栏内的 HTML/SQL 作为文字保留。不承诺控制任意第三方阅读器插件。

实现及独立审查复现了跨块引用和围栏反例：引用定义可激活其他块中的图片/链接；宽泛 `splitlines()/strip()` 会把缩进或 Unicode 空白误认为闭合围栏，吞入后续事实。现用同一次 markdown-it 解析的 `env.references` 拒绝围栏外引用定义；以公开 Token 的源行跨度与正文 LF 行数判断真正闭合，不重写一套缩进规则。顶层缺闭合可补齐，保留原空白；列表/引用内缺闭合则明确未完成，完整嵌套围栏仍支持。

可见性反例 `font-size:0`、极小字号和完全透明前景色同样纳入移除并提示的范围。字号只接受 12–64px 或等价 rem，以现有报告正文可读性为依据；背景透明仍允许。真实浏览器核对这些具体反例，不据此声称能自动保证任意配色对比度或模型设计质量。

安全处理不得删除代码事实、来源或限制。正常内容和目标排版被规范化后能否保留须实际验证；不支持的构造提供有限、可操作的说明。不改 SDK 私有历史或把片段送入普通聊天 DOM，文件绑定后不在重发时另做“自动修好”。

### 5.1 A3：规范化、改写与拒绝的分类

| 情况与样例 | 处理及验收 |
| --- | --- |
| 已有回答 schema/引用/本地文字预算不合格 | 沿原一次无工具改写；第二次仍不合格则失败，不扩大改写额度 |
| 可读内容保留的序列化规范化，如标签大小写、属性顺序或片段闭合调整 | 在文件准备时规范化，不消耗改写；断言目标文字、顺序及正常排版保留，不能只比较源码是否相同 |
| 移除不支持行为/格式后可读主体仍完整，如事件属性、外部资源属性或不允许的样式 | 规范化后交付，代码附固定说明“部分不支持的格式已移除”；说明不回显危险原文/URL。验收正文、事实和来源仍可阅读，不以任意删内容冒充此类 |
| 清理后没有可读主体，或已确定无法保留要求显示的文字/代码、解析失败或资源边界超限 | 明确报告未完成，不按“清理成功”交付，不自动改写或重跑查询；保留按原链路可独立交付的其他部分，整体状态不伪装完整 |

R0 选定清理器后，为后三类各给出可复现正例和拒绝/损失反例，记录实际行为；未转义字符串的语义歧义按 A2，不靠解析后的 DOM 反推原意。默认不新增 HTML 安全改写流程；只有 R0 找到可确定、可给固定原因且值得模型自修的规则，才通过现有公开预检接入同一个判定函数，并据具体反例调整本分类。

同一次文件准备只对每个模型片段生成一次安全结果，附件、容量试排/分卷及纯文本预览复用该结果；不在输出预检和文件准备中重复完整清理，也不在每次试排时再清理。不新增持久缓存或报告平台。预检默认只保留原 schema/引用/预算检查；若按上述例外增加判定，也不重复生成安全内容。

## 6. 报告 Skill

新增短 `report_writing.md`，随包可信发布，复用 instructions 装配，不带自动执行脚本。**A4：在每轮飞书 Agent 的渠道指引处装配，不放进数据库 Skill 的 `if not targets: return base` 分支**；无 StarRocks 目标、仅有监控源或无事实的一般解释也必须获得指南。Web 保留现有不支持文件的说明。飞书普通轮次也会读到 Skill，保持简短，R3 记录其对普通问答的 token 影响。

指南教 Agent 明确受众与必要范围、按事实补证、组织结构和风格、放置相邻事实块、自查结论/单位/时间/失败来源及建议优先级；不强制章节、组件、配色、固定工具顺序或每段机械引用。HTML 普通文字转义要求按 A2。

同步核对现有 `report_note`：保留与本计划相容的“未指定时默认 MD、明确 HTML 时选 HTML”“由代码分卷”；补明单块不可拆、正文由模型编写以及预览由代码提取，不机械删除旧规则或让 Skill 与内联提示互相矛盾。`awaiting_user=true` 不生成文件，即使文字误含 HTML，也沿普通文字展示，不能解释为聊天 DOM。

已有证据足够就停止调查；不足且无法在权限/预算内补齐时，交付更短且明确限定的报告或必要澄清，不为篇幅继续查询。格式变化不应重查已得事实；确有业务结论需要时允许补证，记录原因和成本，不硬性要求报告与普通回答查询次数相同。

Skill 明确片段/CSS 子集、正文与事实的不同身份，不把返回行数当总量、看板定义当实时状态、证据不足当整体健康，也不声称附件已送达。它改善质量，不承担权限、网络阻断或逐句真实性保证。

## 10. 调研依据与重评条件

- [nh3 API](https://nh3.readthedocs.io/en/stable/index.html)：候选片段清理、属性/样式处理能力；具体版本与值处理须 R0 验证。
