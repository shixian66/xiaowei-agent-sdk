## 3. 推荐方案

### 3.1 安全事实的纯文本只交关键事实

在 `business_text` 现有 v4 安全巡检分支生成覆盖和检查项后，结束该事实的渲染，不进入样本逐行循环或附加历史 brief 行数摘要。通知和纯文本 `Delivery.content` 共用这个选择，避免两个出口重新分叉；它也影响请求结果重建的纯文本，具体使用方见 §2。卡片、Web 表格与 MD/HTML 明细取自 facts，不依赖这段样本循环。

单个事实依次包含：数据范围及采集时间、覆盖行、五行检查计数及非零操作分项、必要提示、有样本时的一行：

> 代表样本 N 条未在消息中列出，可在会话中继续追问

`N` 取当前渠道获准 presentation 的样本行数，不用 `matched_rows`、`omitted_samples` 或候选数冒充。零样本时不显示此行，沿已有计数和“无审计记录”提示区分无命中与无数据；提示不承诺过期或未保存数据可以恢复。

此规则同时适用于该工具的 full、本轮 brief 和历史 brief；full 仍决定其他载体如何展示，不要求 Agent 为通知刻意选 brief。不向纯文本追加技术 JSON、Query ID 或另一个附件。B 的可信未完成前缀保持在 blocks 之前；正文中模型文字及其他事实的相对位置仍按 blocks 原序，代码不把结论或分析搬到前面。纯文本安全事实直接输出可读字符串，不调用 JSON 字符串编码加外层引号；原有控制字符显示处理和发送前 mention 中和保留。

其他工具的 note、字段、表格、引号、换行以及动作材料行为不变。v2/v3/Legacy 的历史布局保持既有语义，不用本次修复重构旧路径。

### 3.2 模型概括样本，保留说明身份

仅局部调整 `database_security.md` 报告段：通知时在现有 text 块概括代表样本中的账号、操作、出现次数、时间分布、执行状态和核查建议；按证据充分程度选择要点，不逐条复述样本，不规定章节或工具顺序。没有相应信息时说明未知，不为凑齐六项增加查询。

概括使用“本次代表样本中”等范围措辞；样本内归类、次数和规律属于模型说明，不冒充程序的全窗统计。现有“AI 分析与建议”身份标签保留，Skill 要求文字中交代这些归纳数字为模型说明，不新增数值解析器或输出校验器。代码的检查表仍是可信计数来源。服务账号、重复操作或 OK 都不自动证明维护获批或攻击成功，不引入例行操作白名单。

与 `report_writing.md` 的自主组织不冲突：沿既有结论先行指导，模型自主选择文字、事实的位置及后续调查。程序只缩减事实明细，不另规定全局正文顺序。

### 3.3 时区：转换时刻，不只换标签

安全事实使用其获准 `window.time_zone`（采集时的 `audit.time_zone`），用现有标准库 `datetime/ZoneInfo` 将带 offset 的窗口起止与采集时间转换为本地 ISO 时刻，保留日期和 offset，并显示时区名称。例如 `07:00+00:00` → `15:00+08:00`，不能仍显示 07:00 却只标 Asia/Shanghai。

复用 [B §3/B4](2026-10-23-security-inspection-incomplete-results.md) 约定由先实际需要的切片提供的轻量时间格式化函数，用于覆盖行、`fact_scope` 采集时间及报告样本章节；不要求必须先有 B 的函数才可实施，不另造第二份规则。Web `_view` 仅对安全事实把现有响应字段 `captured_at` 格式化为相同时刻的本地 ISO 值，沿现有 DOM 展示，不加 presentation 字段或在 C 修改 JS。其他工具不转换，底层 `DeliveryFact.captured_at` 不改。

此项和下节计数文案是共享安全展示的有意修正，卡片/Web/文件可同样受益；样本表格、折叠、SQL 技术区和其他工具外观保持原有行为。样本自身 timestamp 已由 Adapter 按审计时区生成，本次不重解释样本时间。

旧证据若缺少可用时区或带 offset 的时间，保留实际原值/缺失标记并说明未转换，不猜当前配置或默认上海时区，也不为展示失败拒绝整条回答。新记录继续信任现有采集契约，不增加第二套配置校验。

### 3.4 零下界与完整性

只改安全检查项的共享显示，不改统计定义：

| 已有可信状态 | 检查项显示 |
| --- | --- |
| 分类计数完整 | 仍显示实际数值；零为 `0`。 |
| 计数不完整，已确认大于 0 | 仍显示 `已确认至少 N 条`。 |
| 计数不完整、已确认 0，已知无法判定候选 N > 0 | `未发现（另有 N 条无法判定）`。N 仅取 `unclassified_candidate_rows`。 |
| 计数不完整、已确认 0，候选截断且无法判定候选为 0 | `已读取候选中未发现`；覆盖/必要提示说明候选未读完、未读数量未知。不能虚构“另有 0 条无法判定”表示已检查全窗。 |
| 计数或无法判定数量缺失 | 保留 `未提供`，不按 0 补齐；零命中描述限于已判定部分。 |

候选截断和已知无法判定同时存在时，保留二者说明。全窗超长数不加进 N；ERR 仍是读取时的全窗聚合，不改成下界。只省略样本不降低计数完整性。

### 3.5 代理 open_url：本次仅评估

用户补充确认：通知不跳转到小维 Web UI，尚不知道公司代理能否省略 `openUrl`。这是链接目的地的产品取舍，不是省略字段已获验证。

本次保留现有必填契约，公司配置由管理员选用其他合适的业务页面，不默认生成小维 Web UI 链接；不新增 URL 黑名单或配置校验。具体页面地址留在公司配置中，不需要发到对话。若希望完全没有跳转链接，待公司确认省略字段的行为后再调整协议。

省略 `openUrl` 的公司行为尚未确认；不移除必填校验，不发送 null/空字符串试探，也不改现有代理协议测试。公司后续确认“整个键缺省”能否正常投递、消息外观及业务成功响应依据；仅 HTTP 2xx 不证明群内收到。无需提供代理 URL、Token 或业务正文。

若后续证据确认可省略，再单独明确契约调整：未配置时省略键、有配置时继续 HTTP(S) 校验及原值发送，补两种载荷测试。它不阻断本次通知精简，不提前实现开关或兼容分支。

备选是只让 Agent 选择 brief 或在通知中保留前几条样本：前者不能解决当前纯文本循环，后者仍占正文且用户已决定不逐行列样本，均不采用。也不在发送后用正则删样本，避免破坏模型文字和其他工具结果。
