# CloudCanal 一期设计与实施计划

> 文档版本：v1.2，2026-10-23；需求与架构 D1 已确认，当前仅授权文档修订与必要离线检查。功能开发、真实模型/公司服务调用、发布、合并与部署仍未授权。

**目标：** 用户发起任务查询、延迟或失败排查，同一个 Agent 自主取证、交叉验证并给出有依据的原因判断和可验证的处理建议。

**架构：** 复用现有 SDK Loop、MCPIntegration、Governed Tool Layer、Evidence、Session 和交付链。最小增量是 CloudCanal 的已核实工具契约、治理接线与必要投影；日志语义分析和跨源推理交给 Agent。

**技术基线：** `1de7b79d61e0c934c5235a522dceb96ccd28aaf5`；Python 3.11，锁文件为 openai-agents 0.22.3 / mcp 2.2.0 / openai 3.20.0 / httpx2 2.13.1。版本核验和有界离线结果见 [handoff](../../../AGENT_HANDOFF.md#cloudcanal-phase1-status)，不代表 CloudCanal 兼容。

**权威来源：** 产品范围、数据边界和 D1 选择只在 [ARCHITECTURE §5](../../../ARCHITECTURE.md#cloudcanal-mcp) 维护；协作、验证与审查按 [AGENTS.md](../../../AGENTS.md)，版本与证据见 handoff。本文件唯一维护 C1—C5、接口核实记录、实施依赖和验收方法；[DEVELOPMENT_PLAN](../../../DEVELOPMENT_PLAN.md#8-p4-监控增量与之后的扩展) 只索引阶段；README 只在入口真实可用时补使用说明。

## 1. 固定任务样例

以下为验收情境，不是生产故障事实。业务问题、成功标准和不可接受结果沿用到计划、开发、审查及用户验收；CC0 补齐实际字段与合成/获准脱敏数据，不借换数据改变判定标准。正例证据充分时必须给出具体判断；只会拒绝或报告证据不足不算能力达标。

| 编号 | 用户操作 → 系统行为 → 用户看到的结果 | 固定成功标准与关键反例 |
| --- | --- | --- |
| C1 任务查询 | “生产中同步订单表的任务现在怎么样？” → 定位任务、必要时消歧，按需取得当前阶段与指标 → 任务、状态、延迟和数据时间 | 覆盖同名任务、多页和空结果；正确关联当前阶段与源目标。同名/环境不明先澄清；漏页不得声称查全；旧阶段或过期指标不冒充当前 |
| C2 延迟排查 | “这个任务为什么延迟，查最近十分钟。” → 自主选窗口指标、日志和相关监控验证判断 → 瓶颈、依据、未确认项和下一步验证 | 正例提供目标端写入受阻的支持证据与短暂 Worker CPU 升高的干扰；定位证据支持的写入瓶颈，区分现象与更深层根因。当前单点不能代替十分钟趋势，时间相关不能单独证明因果；初始假设遇反证应调整 |
| C3 停止任务 | “列出这个实例当前停止的任务。” → 完成该范围检索，按已有证据解释状态 → 停止任务、已知原因或未知项 | 有可信停止原因时区分正常暂停与故障；没有原因信息时只报告停止/未知，不把 STOP 或 haveException 单独当作故障原因；列表不完整须明确 |
| C4 恢复复查 | “刚才那个任务现在恢复了吗？” → 对已确定任务取新证据并按需比较 → 当前运行和积压恢复情况 | 取得新状态/指标，标明新旧时间；RUNNING 不等于积压已追平。历史只能证明过去；刷新失败不得用旧值给当前健康结论 |
| C5 失败排查 | “这个任务为什么失败？” → 在大量重复报错中读取故障时段和异常上下文，按需交叉验证 → 关键错误、原因判断、处理步骤和恢复判据 | 正例包含明确的目标端权限错误、重复重试和无关旧异常；准确识别当前失败原因，建议核对受影响对象的权限/变更并验证写入恢复。不能只摘最后一条错误、拿旧异常解释当前、统一建议重启或声称已执行 |

C2/C5 的多日志样例包含超过单次未筛选返回容量的日志，关键证据不总在默认首段；允许通过源端检索、收窄或续读取得，不固定分页/分片实现。若实际 MCP 无法取得必要上下文，记录能力缺口，不用人为塞入首段让样例“通过”。Agent 可在已获证据足够时提前结束，验收不要求读完无关日志。

共同变体：无指标、日志截断、窗口不覆盖故障、跨源对象标识冲突、权限拒绝、单源超时与预算耗尽。分别验证如何补证、停止以及告诉用户还缺什么；不把这些变体替代正例。回答优先交付结论、关键事实与处理建议，详情沿用现有渠道投影，不默认复述整包日志、工具过程或内部证据编号。

## 2. Agent 的选择、信息与失败行为

### 2.1 交给 Agent 的选择

在已授权源/工具、可信上下文和本轮预算内，由 Agent 选择取证源与工具、筛选条件、分页/窗口、获准监控查询、必要日志上下文、待验证假设、补证方式、是否结束以及回答组织。已有信息足够时不重复询问或查询；仅缺必要业务口径才澄清。工具说明给适用问题和限制，不用关键词路由、无工具前置分类器或程序规定调查顺序。跨源读取仍遵守各源已有前置条件，例如 StarRocks 的环境选择和 SQLGuard；CloudCanal 返回的数据库名称不自行成为数据库查询授权。

“任务详情 → 故障时段日志 → 同时段监控”仅为示意。调用前具备实际工具必需参数并通过治理即可；解释日志时按可信请求或获准返回证据关联所属阶段，返回本身足以关联时无需为确认阶段额外先查详情。新证据完成投影与绑定后才可进入模型，交付仍按当前权限复核。

### 2.2 信息从哪里来

| 信息 | 优先来源 | 缺失时的处理 |
| --- | --- | --- |
| 可用实例、工具、数据范围、身份和预算 | 可信配置、当前授权、RunContext 的受限元数据 | 配置/授权缺失不由模型补造；隐藏不可用工具，说明能力或权限缺口 |
| 本次环境、业务任务和对象 | 用户要求、可信 `server_id`/管理员 `instructions`、仍有效的会话上下文；必要时读获准目录 | 如“生产”已能唯一对应则直接使用，不重复澄清或查询；真实歧义才问用户。权限范围不等于已选对象，现有信息不足才论证新字段 |
| 任务/阶段 ID、源目标、Worker、同步对象 | 可信上下文、CloudCanal 获准返回（含日志自身标识），必要的既有可信映射 | 已能从工具取得时自行查；标识冲突先核对，无法确定才问具体对象，不猜关联 |
| 故障时间、业务口径、可接受延迟 | 用户要求、可信当前时间/时区、相关事件和指标 | C2 使用明确十分钟；未给时间可从当前异常取有界线索并说明窗口，涉及特定历史事故却无法定位时问时间。未给 SLA 不编造业务阈值 |
| 指标含义、单位、采样时间和日志覆盖 | 锁版工具契约、指标元数据、返回值 | 采集时间与求值/日志时间分别记录；缺失写未知，不用创建/修改时间填充采样时间 |
| 根因与下一步建议 | Agent 综合已获证据形成推断 | 事实、推断、未确认条件分明；建议说明目的、前提、预期观察和恢复判据，不声称已执行 |

日志、配置描述及工具返回中的文字均为待分析数据，沿用现有不可信输入边界；模型不能据此获得新权限或改变端点。

### 2.3 错误修正、继续与停止

下表是现有契约及已确认 D1 的应用；代码应返回已有固定状态/原因和允许修正的信息，不把原始异常、连接信息或敏感日志当作错误提示。字段与具体状态按现有 `tools.py`，不另造通用错误框架。

| 情况 | Agent 与系统行为 | 用户看到的结果 |
| --- | --- | --- |
| 必需信息/本地参数可修正，且 `retry_this_turn` 等现有反馈允许 | 利用可信上下文补参数、调整请求或澄清；调用前仍治理；受剩余预算限制 | 得到结果，或明确仍缺的信息；不反复发送同一错误调用 |
| 请求前超出已证实的响应容量约束 | 仅按 §4.4 可推导的界限作本地可修正拒绝，零远端 I/O；Agent 可调整参数，复用现有反馈和预算 | 说明可调整的参数及界限，不声称已经读取结果 |
| 已有 Prometheus/Grafana 等可修正错误 | 按其已批准闭集语义和 `correction_allowed` 修正，保持原有次数/期限规则 | 调查继续；不能借换工具、来源或参数绕过权限与预算 |
| CloudCanal 远端参数错误/对象不存在 | CC0 核实真实表示。当前没有批准 CloudCanal 专用可修正类别；成功响应中的空列表可用于继续定位，远端业务失败不冒充空列表 | 未核实的执行后错误按 D1 记该源未核实；若确需新增可修正类别，先补本计划“新增限制”和架构取舍，再实现 |
| 空结果、部分结果、日志截断或缺指标 | 仅指成功返回且契约有效的有限结果；Agent 可在权限/预算内补证或继续分页。传输接收超限不属于此类 | 说明实际覆盖；缩窗或过滤后的子集不冒充用户要求的完整结果 |
| 已发请求超过 `max_response_bytes` | 当前 transport 抛错，D1 下按执行后失败停止本源本轮，不能再缩窗、续页或换同源工具；不生成成功 Evidence | 明确本源未核实；只有其他获准源仍可调查。接入前须完成 §4.4 的容量核实，不能承诺超限后自修正 |
| 本地无权、范围拒绝、授权暂不可验证 | 按固定拒绝反馈停止相关操作，不据此扩大其他源权限；最终交付再复核 | 权限/不可验证说明；仍可使用的其他获准能力按现有契约处理 |
| 已登记 CloudCanal 读取的超时、不可达、上游拒绝、业务/协议失败或结果未知 | 按 [D1](../../../ARCHITECTURE.md#cloudcanal-mcp) 复用失败记录与本源本轮停止机制；不重放；可调查其他已授权源 | 代码展示失败源、未核实和实际成功范围；全失败时只能给标明未经数据验证的建议 |
| 整轮预算/期限或取消 | 停止后续取证，沿用应用已有收尾路径；取消不证明远端已停 | 已完成范围、未完成项或既有受控终止提示，不虚构结果 |
| Evidence/Session 存储、归属或最终权限/交付验证失败；非 D1 范围的执行后失败 | 沿用现有整轮终止/相关交付阻断，不因自主性降级为正常调查结果 | 受控失败；不把未保存/未获准的结论当成功发送，不自动重跑任务 |

D1 下的来源停止以当前登记的 `target_id` 为界，通常为一个静态 CloudCanal 源；不能换该源的另一工具继续请求。现有下一轮有界连接恢复可复用，但恢复连接不是重放失败查询。用户明确要求再查是新任务，仍需当前授权；不是失败调用的自动重试。

## 3. SDK 与模块复用、关键调用链

已在独立虚拟环境核对锁定包的公开签名，并运行现有真 SDK/合成协议用例；具体检查及结果只记 handoff。官方 SDK 运行时接入与 hosted MCP 的区别见[官方说明](https://developers.openai.com/api/docs/guides/agents/integrations-observability)，实际签名以 0.22.3 为准。

| 公开能力/现有模块 | 复用方式与必要增量 |
| --- | --- |
| `Agent`、`Runner.run`、`FunctionTool.on_invoke_tool`、SDK Session | 沿用单 Agent 和受治理 function tool；不新增 Planner、手工模型循环或会话存储 |
| `MCPServerStreamableHttp` 的 `list_tools/call_tool`、`httpx_client_factory`，`MCPServerManager` | 复用 `mcp.py` 的连接、核约、关闭与固定端点 transport。SDK 工具过滤可以限制发现结果，不能替代每次调用前的业务治理 |
| `config.py:MCPServerConfig`、`runtime.py` | 现有配置只接纳已选策略；补已核实 CloudCanal 的工具/源映射和本轮可见性，不把远端目录整体交模型 |
| `governance.py`、`models.py`、`tools.py` | D1 接入同一封闭读取策略集合；核对所有使用方：runtime 准入、mcp 异常分类、governance 失败/停止、evidence 失败源复核及 app 说明注入。当前不含 CloudCanal；复用预算和源停止，不扩大到所有 MCP |
| `mcp.py` 的结果解析、现有 `ToolPolicy/Projection` | 为目标版返回语义补薄转换；复用类型、字段、容量及 Evidence 检查。SDK 也有原生 MCP guardrail 接口，但重接这条已有治理链无已证实收益 |
| `evidence.py`、Session、`app.py` 及现有展示/报告链 | 新工具事实和失败记录进入同一历史与交付验证；不改回答 schema、SDK 表或引入日志仓库 |
| 既有监控工具、`src/xiaowei/skills/` 工作方法 | Agent 按需写 PromQL、补证；只补 CloudCanal 语义说明，不复制日志分析或跨源推理能力 |

业务调用路径：

```text
静态配置 → SDK 连接/list_tools → 本地契约核实 → 本轮授权工具集合
用户入口 → 现有单 Agent / Runner
         → 受治理 FunctionTool → GovernedTools.invoke（当前权限、参数、目标、预算）
         → MCPIntegration → SDK call_tool → 外部 MCP
         → 契约解析与结果投影 → Evidence → 模型继续调查
         → 最终 Evidence/权限验证 → 原有 Web/飞书交付与受治理历史
```

启动/工具发现与业务调用不是同一条授权动作：沿用可信配置的连接生命周期，业务请求必须在治理之后。每轮工具集合沿用现有装配，不并发修改共享 Agent。

预期受影响范围为上述模块和对应测试；普通内部函数、私有类型拆分和具体文件新增数量留给开发。仅当锁版契约确需独立薄模块才拆文件，不先创建接口/工厂。预计无需新依赖、数据库迁移或入口；实际契约推翻这一假设时先补方案与恢复分析。

## 4. 待核实的接口、数据与权限契约

### 4.1 连接与运行前置

**全部待确认：** CloudCanal 产品/MCP 版本、部署实例、真实 transport/认证方式、只读服务身份、实例/任务可见范围、真实 `tools/list` 与成功/失败样例。用户稍后补版本与连接方式；凭据仅用安全引用，不收正文、不把含凭据链接写进仓库。

现有小维支持静态 HTTP(S) Streamable HTTP、可选 `env:NAME` Bearer（注入 `authorization` 头）、固定完整端点、不跟随重定向及接收上限。`config.py` 要求远端工具名匹配 `[a-z0-9_-]{1,64}`，与 `server_id` 组合后不超过 64 字符；`runtime.py` 还要求等于 policy ID 末段。驼峰名、含查询参数/片段的端点、其他认证或资源读取形式均须先说明最小适配及治理影响，不能把示例名称改写后当作实际可调用工具；不预建兼容层。

### 4.2 工具说明要落到的契约

下表为候选能力及 OpenAPI 线索，**不是已确认 MCP 工具名称或输入要求**。CC0 只核实固定样例实际需要的工具；映射/异步步骤仅在已有读取不足时补查，不默认实现。对选中工具固定真实名字/schema、适用问题、必需输入、返回限制、只读效果和已支持错误反馈。

| 候选能力 / OpenAPI 参照 | 适用问题与输入要求 | 最小返回与限制 | 修正与继续 |
| --- | --- | --- | --- |
| 分页列表 `listbypage` | C1/C3；已确定源，合法页码/大小；按真实支持的 ID、名称、状态、源目标、同步对象筛选 | `jobVos/allJobCounts`；任务 ID/名称、阶段/状态、源目标标识。核实排序、页界、总数与变化中的重复/遗漏，不承诺跨页同一快照 | 本地缺参按现有反馈补正；成功空页可核实条件；超限后的缩小结果不得冒充完整列表 |
| 任务详情 `queryjob` | C1—C5；明确的任务 ID | `dataJobId/dataTaskState/currTaskStatus/dataTasks`；阶段 ID/类型/状态，`haveException/healthLevel/consoleJobId`、必要源目标与 Worker 标识；多阶段和历史异步操作需区分 | 已有目录可消歧；远端不存在错误的可修正类别待核实，未登记前按 D1 |
| 当前指标 `queryjobmetric` | C1/C2/C4；明确任务 ID | `curTaskType/ccDataTaskStatus/increDelayMs` 及适用的进度；实际健康字段、单位、采样或刷新规则。零、null、未采集、不适用不同；单点不证明趋势 | 阶段不适用可换相关证据；缺指标不推断正常；不凭接收时间补造采样时间 |
| 窗口诊断 `queryjobtuneinsight` | C2/C5；相关 `dataJobId/dataTaskId` 和已确定的起止时间 | 实际窗口、指标时间点/状态、任务主日志和适用的提交日志；核实检索/续读、阶段可用性、日志保留/截断、响应包形式、容量和远端采集成本 | 成功的部分结果可继续补证；缺少检索能力列为功能缺口，不靠模型摘要恢复遗漏；业务/协议失败按 D1 |
| 对象映射 `queryjobschemabyid`（按需） | 列表/详情不足以按库表定位或判断映射时；明确任务 ID | 源目标 schema、mapping 的必要对象标识及匹配/排除规则；可能是字符串内嵌 JSON | 工具可获信息自行补；不提前全量同步元数据；错误语义未核实前按 D1 |
| 异步操作详情 `queryconsolejob`（按需） | 失败在创建/启动步骤时；从可信关联取得 `consoleJobId` | 关联资源、操作类型/状态、起止时间、步骤/状态/错误；步骤上下文可能含敏感内容 | 仅当操作对象与故障时间对应才作依据；本期读取已有操作，不执行重试/忽略动作 |

官方调查入口：[分页](https://www.clougence.com/docs/openCenter/openApi/dataTaskApi/api_datajob_listbypage)、[详情](https://www.clougence.com/docs/openCenter/openApi/dataTaskApi/api_datajob_query)、[指标](https://www.clougence.com/docs/openCenter/openApi/dataTaskApi/api_datajob_queryjobmetric)、[诊断](https://www.clougence.com/docs/openCenter/openApi/dataTaskApi/api_datajob_queryjobtuneinsight)、[映射](https://www.clougence.com/docs/openCenter/openApi/dataTaskApi/api_datajob_queryjobschema)、[异步步骤](https://www.clougence.com/docs/openCenter/openApi/asyncTaskApi/api_consolejob_queryconsolejob)。OpenAPI 的鉴权不直接当作 MCP 鉴权。

选中指标/诊断读取时，核实健康字段表/例差异和诊断返回形式（OpenAPI 为文件）；以目标 MCP 的实际契约为准。若选用创建详情作补充，工具说明须明确它是配置线索，不能代替失败日志；不恢复未选接口的必查要求。

### 4.3 返回、数据和权限

- 成功须同时满足传输/MCP 及真实业务结果契约；`HTTP 200`、`is_error=false` 不单独证明业务成功。薄转换先识别实际业务状态，再投影结果；通用 `_payload` 的 `extra="ignore"` 不替代这一步。`code` 失败且 `data:null` 必须失败、无成功 Evidence；null 不转换为空列表，成功空列表按真实契约区分。
- 请求绑定的源、任务/阶段、筛选与窗口构成可信查询范围。冲突校验只比较契约指定的结构化身份字段；日志正文或关联对象提到其他 ID 不算冲突。没有回传 ID 时可用可信请求标记查询对象，不伪称服务端回传，也不额外查询重复证明。
- 结果保留必要任务事实、指标含义/单位/时间、日志片段与可追溯定位、实际覆盖/截断/缺失标识。事件时间、查询窗口、服务端采样时间、客户端采集时间分别表达；未返回值写未知。原始包、模型、Session、渠道及历史复核按 ARCHITECTURE §9，不再复制一套策略。
- 错误文本、日志和配置可含密码、连接串、SQL、主键与业务值；按获准内容选择字段/上下文，优先利用源端处理。不声称正则或字段白名单能识别全部敏感信息；若无法提供合规且足够的证据，相关能力保持未验收，不静默裁掉关键原因后声称诊断完整。
- 现有源级授权只有在“该源服务身份可读的实例/任务均属于该用户批准范围”成立时足够。否则先选可限制范围的远端身份/实例配置；若仍需对象级授权，明确缺口和最小接线，再更新架构，不能默认把主账号权限授予聊天用户。
- 接收范围确认须使用实际入口语义：Web 无登录、访问者共用 `operator_id`；指定飞书群全员同权、共享上下文与结果。按这些实际接收人确认获准日志内容，不按“仅提问者可见”设计投影。
- 跨源标识来自可信配置或获准证据，时间/对象无法对应时 Agent 核对或澄清，不以相似名称强行关联；不把推测关联写成代码已核实事实。
- 结果形式优先复用现有结构化内容/单段 JSON 解析。固定样例确有需要且整体成本更低时，可评估资源引用或文件读取适配；决定前核对 SDK 公开能力、固定可信目标、凭据与容量边界，不自动抓取返回链接。
- Agent 用已获必要证据形成简洁结论与建议；关键结构化事实由现有代码投影。事实真实只意味着与获准来源一致，根因质量仍按 C2/C5 验收。

### 4.4 响应容量与单源期限（B1）

已核实的本地路径是 `mcp.py:_BoundedStream` 超限抛错 → MCP/治理执行后失败分类 → D1 本源本轮停止；成功截断与接收失败不同。CC0 对每个选中工具记录服务端实际执行的分页/窗口/行数/过滤参数、响应形式与容量依据、所需范围的分次覆盖方式，以及与 `max_response_bytes` 的关系。

只有远端契约能界定实际响应字节时，才据其单项大小、截断方式及 JSON/SSE 等封装开销推导请求前界限，接入已有本地可修正拒绝。页数、行数或短窗口本身不保证字节上限；代表样本不是最坏上界，不能据此生造“安全窗口”或配额。无法界定时记录对应样例能力缺口，核实源端有界读取或其他必要路径；若仍须超限后缩窗，参照既有 Alertmanager `response_limit` 提出具体类别、重复请求和预算语义，由用户决定后修订契约，不自动继承该例外。

每个 Server 当前共用一个 `timeout_seconds`。CC0 记录选中工具（含最慢诊断）在代表工作量下的耗时及测量范围，据此配置源期限并核对整轮预算；超时仍停止该源，不拆 `target_id` 绕过 D1。容量或期限缺口按工具标明受影响的样例/切片；CC1/CC2 开工前须解决各自依赖工具的 B1 路径，不能以本次文档修订当作已关闭。

## 6. 切片、依赖与验收

验证按实际变更分层：新增字段、单位、业务错误和截断用契约/转换小测试；新增接线、D1 和日志投影用少量真 SDK、合成 MCP 与实际隔离存储的集成用例。公共权限、预算、存储和历史机制复用现有回归，仅为新分支或覆盖缺口补用例，不逐工具、错误、渠道复制完整链路。固定模型证明链路，真实 Agent 能力在 CC3 验收。

§1 七个共同变体各指定一个主验收层：无指标、成功日志截断、窗口不覆盖故障、跨源对象标识冲突在 CC3 验 Agent 补证与限制表达；权限拒绝、单源超时、预算耗尽在离线集成验执行及用户可见状态。新增转换的字段保留/拒绝仍用小测试，不在两层重复同一业务断言，也不做全排列。

### CC0：核实可完成任务的实际 MCP 契约

- **依赖/产出：** 用户补版本与连接方式；将选中工具的 §4 契约补齐，逐工具记录 §4.4 容量路径、耗时/源期限及受影响样例，并确认实际 Web/群接收范围。必要协议样例进入对应测试。
- **成功：** CC1 所需任务/阶段/当前指标可取；明确 C2/C5 所需日志/窗口与跨源标识的可用性。选中工具有真实 schema、代表性成功返回及适用错误契约；同一错误契约留代表样例，不逐工具重复采集。
- **关键失败：** 仅尾部日志、无时间/对象关联、资源链接不兼容、认证携敏感 URL、权限只能用越界主账号、返回语义不清。指出阻塞哪个样例及最小备选，不拿通用 SDK 通过关闭缺口。
- **验证：** 复用已有 SDK/协议证据，仅补实际差异；真实只读核实须获授权且工具已确认无业务副作用。效果不明时先查文档/厂商；仍未知则提出隔离实例核实方案，取得覆盖可能效果的授权后再执行，隔离本身不授予权限。
- [ ] 完成所选工具契约、效果、容量/期限及数据/接收范围确认；各实施片只在自身依赖的 B1 路径解决并获开发授权后推进。

### CC1：任务、状态、当前指标闭环

- **依赖/产出：** CC0 必要工具及其 B1 容量路径已解决 + 功能开发授权。复用既有模块接入任务列表、详情和当前指标，完成 C1/C3/C4；D1 从首个工具起生效。
- **成功：** 正式 Agent 路径取得正确任务/阶段/指标并可追问；空配置/源不可用不影响原有功能；单源失败能保留其他获准源的调查能力与明确状态。
- **关键失败：** 同名/跨实例、重复页/漏页、STOP 混同失败、null 混同零、指标过旧；结构化主身份冲突须失败，正文提及其他任务仍正常成功；HTTP 200 + code 失败 + data:null 无成功 Evidence，null 不冒充空列表。前置容量拒绝/撤权零远端 I/O；接收超限/结果未知只发一次、无成功 Evidence、本源停、不重放；Evidence 存储失败仍整轮终止。
- **接线完成标准：** §3 各策略使用方均覆盖 CloudCanal；带失败源回答在仍获准时可历史读取和重发，撤权后仍拒绝。本轮仅 CloudCanal 工具可见时，注入说明与“该源/读取失败源”等文案符合语义，不要求不存在的监控/数据库工具。现有 `ServeConfig.targets` 至少一项的部署约束不变，此验收不等于新增零 StarRocks 配置启动支持。
- **验证：** 按上述分工验证字段转换与任务工具接线，选正常、拒绝及 D1 场景证明新策略进入现有治理、保存与交付链。复用/扩展 `test_runtime.py`、`test_mcp_integration.py`、`test_monitoring_read_recovery.py` 及相关 Evidence/展示测试。
- [ ] 定义上述可观察预期并建立能复现关键失败的测试。
- [ ] 实现最小接线，运行受影响检查，以具体 SHA 独立审查 MCP/权限/数据链；缺陷解决后再推进依赖片。

### CC2：日志与交叉排查闭环

- **依赖/产出：** CC1 + CC0 日志/窗口/对象关联契约及相关 B1 容量路径。接入最少的日志/诊断读取，按实际需求补映射或异步步骤；Agent 使用既有监控完成 C2/C5，有界读取增量由实测决定。
- **成功：** C2/C5 正例能取得足够证据；多片日志保留必要上下文及来源，Agent 可检验假设、避开干扰，给出具体处理建议与恢复判据。优先使用同源已有指标，跨外部监控时按实际缺口补证，不强制每次全工具巡检。
- **关键失败：** 首段无关键错误、故障在保留窗外、日志轮转/截断、源目标标签不匹配、毫秒/秒或时区错位、历史异步步骤误关联；敏感文本投影不合约、日志中的伪指令试图改变工具/预算；任一源失败时按 D1 继续其他获准源，不能绕回失败源或改查未授权实例。
- **验证：** 对实际新增的日志转换覆盖分段/大响应/缺失/错误，用代表性集成场景确认新投影进入真实治理/存储链且未遗漏关键证据或误报完整。公共权限、预算和失败停止复用既有回归；同一 C2/C5 材料进入既有模型评估入口。
- [ ] 完成日志取证最小接线及工作方法，验证关键失败与正常链路。
- [ ] 对最终差异及调用链独立审查；权限、数据或错误分类的阻断解决后进入 CC3。

### CC3：固定业务样例的真实验收

- **依赖/产出：** CC1/CC2 通过相关离线检查与独立审查；用户批准真实模型 Profile/数据/成本、公司只读范围及入口验证。保存具体代码 SHA、模型配置、Server 版本、数据版本/时间窗和结果记录。
- **运行前待决定：** 与预算一起固定每个 C1—C5、上述能力变体及渠道样例的次数、通过阈值和失败后的复测范围。建议已知原因的 C1—C5 各 3 次、各次均达 §1 标准；这是重复性抽查，不据此宣称统计成功率。治理违规任一次即不通过，能力与治理分别记证；具体次数/阈值未确认前不运行 CC3。
- **成功：** C1—C5 均达到 §1 标准；真实模型自主选工具/查询、补证并形成正确限定的结论；正式入口交付可读结果，C4 实际刷新；关键失败时状态清楚。能力与权限边界分别记证。
- **关键失败：** 离线成功但真实 Agent 不取关键证据、无限补查、错误根因、模型/渠道收到越界日志、源失败误报健康、事实时间不清。按具体失败修复后重跑受影响样例，不改变金标准或仅用负例补齐。
- **验证：** 固定获准模型执行全部 C1—C5，先合成/脱敏已知原因样例，再获准真实只读工具。正式 Web/飞书渠道覆盖代表性的成功与失败/不完整交付，不默认与全部任务及错误做组合。记录工具选择、事实/原因、补证与停止、耗时/调用/token 和可取得的用量；预算先确定，未知成本不虚构。
- [ ] 逐项记录通过/未通过/受环境阻塞和具体证据；未真实验证不标为交付完成。
