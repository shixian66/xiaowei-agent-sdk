## 方法与边界

复用正式 `serve` / Web `/api/turns`、OpenAI Agents SDK 0.22.3 Runner、治理、SQLGuard、
Evidence、PolicySession 和真实 PostgreSQL（本机隔离测试实例 55432，每用例独立数据库）。
Vertex 风格模型响应通过现有 HTTP transport 替身返回；StarRocks 只替换底层连接驱动，
监控使用真实 SDK MCP Client 与 loopback 合成 MCP 服务。端口随机分配，没有使用 8501。

只在测试侧观察现有读取/提交、治理复核和 HTTP 装配路径；不改 SDK、不给产品加测试入口，
不额外回放或探测 Evidence。没有调用真实模型、飞书/Lark、公司 StarRocks 或公司监控源。
脚本已预设工具选择，只能证明执行链、完整回放与边界，不能证明真实 Agent 自主排障或答案质量。

本次共同限额直接来自部署主模板：100 次成功提交、400000 历史字节、604800 秒固定期限，
模型请求/响应各 1000000 字节、单值 4000、单次结果 200000、模型/Session 投影各 400000，
`max_scope_checks=2048`，每轮 `max_turns=16`、`max_tool_calls=16`。
选配监控采用既有 fixture 的 64000 字节 MCP 接收上限，没有为宽结果调大。
低历史/请求对照只改变表中列明的一项，其他保护原样执行。

30 轮混合序列反复覆盖字段/布局并行取证、最多 5 条数据、含中文/换行/引号/反斜杠的原文、
解释、历史短问和监控摘要。普通查询返回 5 行；原文样例返回 1 行、输入值 4000 UTF-8 字节，
含转义字符的 JSON 单值为 4005 字节，实际 Adapter 按既有 4000 上限截短并标记；
测量的是该获准结果，不是证明完整 4000 字节原文已保留。另以每查询 45 行同类值对照结果容量。
这个顺序用于形成可重复负载，不是对 Agent 新增的固定工作流程。

每轮记录：

- `replay_bytes`：本轮开始时实际完整历史大小，采用 PolicySession 同一 UTF-8 JSON 口径。
- `commit_replay_bytes`：现有提交校验看到的历史加本轮候选大小；提交失败的候选并未保存。
- `requests[].bytes/sent`：最终序列化 HTTP 请求体的实际大小，以及是否进入底层 transport。
  超限尝试也记录大小，不能把它误算为已发出的请求。
- 指令、工具声明、生成配置/输出 schema 独立序列化大小；`overhead_bytes` 为移除 contents 后的
  固定开销，子项与整体的包装不同，不能直接相加推算最终请求。
- 真实 scope checks、业务查询、权限探测、依赖读取、DDL/MCP 调用分别计数。
  这些计数不是连接数或 token 数；替身耗时不能估算真实模型延迟或费用。

报告只保存固定标签、配置、大小、次数、耗时和哈希，不保存问题、SQL、值、签名、端点或凭据。
`input_hashes` 分别绑定实际导入的产品源码内容、实际主模板及测量 helper/测试内容。

## 测量结果

以下为一次定向运行观测值，单位均为字节。请求中的证据/调用标识可能使重复运行的数值略有变化，
验收检查真实上限和 I/O，不要求固定字节常量或计时阈值。

| 场景 | 成功交互 / 首次拒绝 | 提交候选回放峰值 | 模型请求峰值 | 首先触及的限制 |
| --- | --- | ---: | ---: | --- |
| 混合排障 30 轮，原配置其他限额 | 30 / 未触顶 | 53897 | 78464 | 无；scope 峰值 8 |
| 原 20 轮、首轮查询后短问 | 20 / 第 21 轮 | 8030 | 29748 | 轮数 |
| 新 100 轮、首轮查询后短问 | 100 / 第 101 轮 | 36351 | 58549 | 轮数 |
| 历史限额降低为 2500 | 4 / 第 5 轮 | 2724 | 27081 | 历史字节 |
| 每轮约 60000 字节 DDL | 6 / 第 7 轮 | 426832 | 451242 | 历史字节 |
| 同轮三查询，各 45 行、每值 4000 字节 | 0 / 第 1 轮 | 545313 | 569406 | 历史字节，已执行三查询但未提交历史 |
| 宽监控 1000 行 | 21 / 第 22 轮 | 413349 | 438343 | 历史字节；MCP 响应峰值 33237 |
| 宽监控 3000 行 | 0 / 第 1 轮 | 0 | 24672 | MCP 响应 99236 超过 64000 |
| 200 对象，四个并行完整列表示例 | 0 / 第 1 轮 | 0 | 106825 | scope 复核，未提交历史 |

提交超字节沿原保护封存为 sealed；开始前轮数拒绝没有新的模型请求、业务查询或权限探测，
已提交轮次不增加。100 轮例每次仍回放完整工具配对和 thoughtSignature，签名由原伪端点核对。
只提高轮数的 active 会话可以继续；撤权、sealed/closed 成功对照仍拒绝，没有重新执行历史查询。

复核成本单独观测：混合 30 轮为 10 次业务查询、199 次权限探测、567 次依赖读取、5 次 MCP 查询；
100 轮轻量追问为 1 次业务查询、501 次权限探测、1503 次依赖读取。
大目录对照在已用 2000 scope checks 后无法再准入下一批，按 scope_unverifiable 失败；
共 2800 次权限探测、零业务查询。scope 预算包含分阶段校验与批量准入，不能与探测总数混同。

### 模型请求边界

| 限额 / 拒绝阶段 | 首次请求 | 工具返回后尝试 | 被拒请求 HTTP I/O | 本轮业务查询 |
| --- | ---: | ---: | ---: | ---: |
| 请求 500；首次请求 | 21947（未发） | 无 | 0 | 0 |
| 请求 30000；工具返回后 | 21947（已发） | 566677（未发） | 0 | 3 |

后一种失败不代表“未执行查询”；SDK 历史未提交，也没有自动重放。
30000 是刻意降低的请求对照值，与飞书发送请求上限无关。

## 复现与检查

在干净候选和锁定开发环境，使用独立测试数据库：

```bash
uv sync --extra dev --frozen
SDK_TEST_POSTGRES_URL=postgresql+asyncpg://postgres@127.0.0.1:55432/postgres \
  .venv/bin/python -m pytest tests/sdk_core/test_session_capacity.py \
  -q -W error --basetemp=/private/tmp/xw-s1-capacity
```

pytest 每次重建 basetemp；各用例的 `capacity.json` 位于其下，兼容状态用例只做断言。
每次报告绑定实际导入源码/模板/harness 哈希，可核对导入版本，不用脚本位置冒充产品版本。

- 基线定向 Session/Vertex/R3：188 passed；新增混合序列在 20 轮模板上确实于第 21 轮失败。

  315 passed、1 failed。唯一失败是本机 Docker 磁盘耗尽导致新 PostgreSQL 初始化失败，

  314 passed（127.33s，含新增 16 项和文档 5 项）；不替代上述 Compose 失败。

## 结论、兼容与未覆盖

已批准的 100 轮调整提高了轮数上限，其他上限原样保留。轻量完整追问可到 100，30 轮混合样例可完成；
较长 DDL、多个大查询、宽监控及大目录复核可能先拒绝，不能由本报告承诺所有排障能聊 100 轮。
不采用自动摘要、尾部裁剪或提高其他上限来凑数；S2/S3 尚不提供更具体的用户原因和提前提醒。

公司现有配置不会自动变；局部设置、旧 active/sealed/closed 行为及回退只看
[运维说明](../../../deploy/OPERATIONS.md#会话轮数的手动配置)。S1 无数据库迁移，回退轮数无需重写历史。

真实模型的工具选择、澄清、修正、长上下文答案质量、token 用量和真实延迟未验证；
也未验证真实 Lark/公司 StarRocks、浏览器或部署。S1 没有修改模型/工具契约，
不将 R7/R3 的例外扩成新的真实模型豁免；私聊或测试群观察仍须另获部署和环境授权。
