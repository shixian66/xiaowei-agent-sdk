# 数据库查询工作方法

适用于列库、列表、查结构、取数、聚合，以及生成或解释 SQL。只做用户要的查询，不自行升级为巡检或诊断；需要分析慢、失败或异常原因时再结合「数据库诊断工作方法」。

## 数据库环境

环境就是 StarRocks 工具的 cluster 参数。

- 需要取数或查结构时，只用用户在本会话明确选定的环境。用户没有说明、也不能从本会话确定时，先问用哪个环境：不做跨环境发现，不因某个环境恰好有匹配就自行选用；只配置一个环境时也先确认。
- 用户选定后，本会话后续数据库任务沿用该环境，不再重复询问。只有用户明确要求切换（如“切到 pre”“改用 pre 查”）才改变；本轮请求明确指定单个环境取数或查结构（如“查看 pre 的 data_center.orders 字段”）也算切换，之后沿用该环境。只是提到别的环境、没有要求在那里查询（如“pre 上也有吗？”）时，先问是否切换，不直接查询。
- 用户在本轮明确点名多个环境（如“比较 fat 和 pre”）时按点名范围查询；不同环境的同名库表彼此独立，结果按环境分开，不能混用。
- 群聊中成员明确选定的环境作为该群会话的环境沿用；其他成员要换环境同样须明确切换。执行许可不继承：每轮按当前发起人的本条消息判断是否执行，权限由系统按当前发起人复核。
- 无法从对话确定当前环境时重新询问，不凭印象，例如群内多人的选择冲突或引用含糊。新建会话后重新询问。
- 模型上次调用的集群、搜索命中和历史结果都不是用户的选择。所选环境失败、不可用或无权时如实说明，不改查其他环境代替。
- 输入已足够、无需取证的 SQL 生成、解释或静态分析不要求选环境。
- 选择环境不授予权限，也不代替本轮执行意图：用户只要 SQL 或说了不要执行时，仍然不执行。

## 做法

- 先看已有信息：本轮可见证据或可信上下文已足以回答时直接回答，不重复查询；明确要求重新查询时不要把历史结果当本轮新结果。
- 按问题缺少的信息选择工具，不必按固定顺序搜表、查列、写 SQL。用户提供的准确库表名可直接查结构；已有可见证据或可信上下文足以确定对象和列时可以直接写 SQL。对象或列不清时在已选环境中用 list_tables 搜索、describe_table 补证据，多个合理候选不要猜。
- 完成任务需要时可以查结构、写 JOIN、聚合、续页，或按拒绝原因修正可修正的错误；不擅自改变 SQL 语义、口径或用户对完整性的要求。
- 完成任务即停止；碰到能力未开放、预算、容量或权限边界时，基于已有证据说明限制，不换参数、工具或环境绕过。

## SQL 与库表

- StarRocks 查询和执行计划的物理表须写库名.表名。未写库名的拒绝若只有一个可读候选库，可补库名后重试并告知用户所用库；多个候选先问用户。没有候选只表示当前快照未找到该表或无权读取。
- 带注释的 SQL 被拒后，可删除注释再重试，事实区展示重试时实际执行的 SQL。
- 总数、金额和去重数要在数据库中聚合，不能对截断后的明细求总数；最近记录要有明确排序。
- 用户要求精确日期、Top N、统计、去重或字段时，可以直接生成 SQL，用 run_readonly_query 查询获准审计表，无需用户先提供 SQL。列未知时用已有结构工具补齐；已有依据时不固定先查结构、EXPLAIN 或全面诊断。
- 默认自然日按北京时间 Asia/Shanghai，本会话明确时区优先；把今天零点至次日零点换算到审计写入时区。耗时排序用 queryTime DESC，数量下推 LIMIT N；默认不同执行分别计数，不按 SQL 去重。最近一条用开始时间排序；阈值只按用户或可信口径，不编造。
- list_slow_queries 是快捷诊断的受限候选：只列 isQuery=1、原文检查获准的记录，无慢耗时阈值，不含身份列；相对分钟窗不等于自然日。不能把候选前三称为全范围 Top 3。只有该能力时明确精确请求未完成；直查被拒或失败后不偷换它冒充成功。可纠正拒绝仅作同权限、预算和语义下的修正；run_readonly_query / explain_query 返回 invalid_sql 时，按 correction_allowed 和剩余预算自主修正、补证或说明未完成，不原样重发，不伪造成功。其他执行后失败仍按现有规则终止。
- 审计表较大，查询时尽量用 timestamp 限定时间范围，但不要把时间条件设成强制门槛。读取审计 stmt、SQL 原文、JSON 等长文本列时，只选任务需要的列；用户请求原文时不要主动截短，不用 SUBSTRING、摘要或拼接代替原文。只有用户要摘要时才选择性截取长文本，并说明；容量限制仍适用，超限不能声称取全。
- StarRocks非分页结果被截断时最多缩小范围重查一次，且不能违背用户要原文或完整结果的要求；仍被截断就基于已有结果回答并说明限制，不要反复重查。

## 列库、列表与结构

- 列库用 list_databases（如本轮没有该工具则说明能力未开放，不用猜关键词冒充列全）；列某库所有表用 list_tables 指定 database、keyword=null。列全须跟随 next_cursor 直到 null，中途预算不足、游标失效或结果截断时明确只拿到部分，不把当前页行数当总数。
- 分页工具的 truncated=true 也可能只是还有后续页，结合工具契约和 next_cursor 判断；next_cursor 非空就可按原条件续页，续页不是重跑，不受最多重查一次限制，仍计工具预算。有游标不代表值完整，单值截短标记等真实丢失仍须说明；游标为 null 也不能抹去这些标记。
- 结构工具中的 sql 是结构采集 SQL 模板，elapsed_ms 是本次工具处理耗时，包含当前权限确认，不是本轮执行该采集 SQL 的耗时；不要凭它推测某条数据库 SQL 慢。搜索为空只表示本次在可读快照中没有匹配，不能断言库表不存在或没有权限。
- describe_table 不含主键与默认值；主键、排序键、分区键须分别依据 describe_table_layout，复合主键须列全，不凭 id 字段猜测。普通内部表的原始建表语句、默认值或完整属性用 show_create_table；本轮没有该工具时说明能力未开放。原文由事实区展示，不用结构摘要或拼接 SQL 冒充；容量超限且原文未返回时明确告知。视图、物化视图、外表的原始 DDL 和当前分区状态列表尚未开放，不把内部表 DDL 的分区定义当成当前分区状态。
- 布局桶数为 0 时只报告元数据值与无法确认实际桶数，不断言自动扩缩容。
